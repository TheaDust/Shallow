# 项目架构笔记

## 技术选型与理由

- 前端：React 18 + Vite 5 + TypeScript（严格模式），依赖钉死精确版本并提交 `frontend/package-lock.json`；无组件库与状态管理库。
- 后端：零依赖原生 `node:http`（`backend/server.js`），无第三方包。
- 路由：手写 hash 路由（`#/` 首页、`#/new` 创建工作簿页、`#/workbook/<id>` 编辑器），前端路由切换不产生新服务端路径。
- 测试：前端 Vitest + @testing-library/react（`frontend/src/*.test.tsx`），后端 node:test（`backend/test/*.test.js`）。

## 模块与入口

- `backend/server.js`：创建 HTTP handler 与服务器。`createHandler({dataDir?, distDir?})` 可注入数据目录与前端构建目录供测试；`start()` 读取 `PORT`（缺省 3000）并额外监听 3301（各自独立的 `http.createServer` 实例，监听所有网卡），`ARC_EXTRA_PORTS=0` 时跳过额外端口。
- `frontend/src/App.tsx`：hash 路由分发（HomePage / CreateWorkbookPage / EditorPage）。
- `frontend/src/pages/HomePage.tsx`：工作簿列表，每条记录含以工作簿名为可访问名的链接与 `Last updated: <值>` 文本；顶部有可访问名为 `New blank workbook` 的按钮（点击进入 `#/new`）与 `Import CSV` 按钮（打开导入对话框，成功后跳转新工作簿编辑器）。
- `frontend/src/components/ImportCsvDialog.tsx`：首页导入对话框（原生 dialog，可访问名 "Import CSV"，aria-modal="true"），含 label `CSV file` 的文件控件与 `Confirm import` 按钮；读取文件为 UTF-8 文本后 POST `/api/import-csv`，成功回调由 HomePage 跳转 `#/workbook/<id>`，失败在对话框内以 role=alert 显示服务端错误且不产生记录。
- `frontend/src/pages/CreateWorkbookPage.tsx`：创建工作簿页；表单含 label `Workbook name` 的输入（默认 `Untitled workbook`）、提交按钮 `Create`、返回首页的 `Cancel` 链接；成功后跳转 `#/workbook/<id>`，失败显示错误并停留在可重试状态。
- `frontend/src/pages/EditorPage.tsx`：编辑器；工作表 tab（role=tab，aria-selected）、公式栏（label "Formula bar"）、WorksheetGrid、以及 Filter views / Data validation / Pivot table results 数据驱动区块与透视结果表上的 Pivot table editor 区域；标题旁有 `Rename workbook` 按钮（aria-expanded），点击展开内联表单（label `Workbook name` 输入预填最后保存名 + `Save` 按钮），空名客户端校验提示 `Workbook name cannot be empty`，改名通过同一串行保存队列提交，失败回退最近成功状态并显示错误。每个 tab 由容器内两个按钮组成：tab 按钮（文本=工作表名）+ 可访问名 `Worksheet options for <name>` 的选项按钮（aria-haspopup=menu、aria-expanded，data-sheet-options=<sheetId>）；选项按钮点击打开 role=menu 菜单（aria-label `Options for <name>`，data-sheet-menu），内含 role=menuitem 的 `Rename` 命令，支持方向键/Home/End/Escape/外点关闭；`Rename` 打开原生 dialog（可访问名 `Rename worksheet`，aria-modal），含 label `Worksheet name` 输入（预填当前名）+ `Save` 按钮；空名客户端提示 `Worksheet name cannot be empty`、同簿重名提示 `Worksheet name already exists`，改名走串行保存队列，失败回退最近成功状态并保持对话框显示错误，成功关闭对话框且 tab 更新；对话框关闭后焦点延迟回选项按钮（避开浏览器模态焦点恢复覆盖）。
- `frontend/src/components/WorksheetGrid.tsx`：ARIA grid（accessible name "Worksheet grid"，aria-multiselectable="true"）；gridcell 以坐标（如 A1）为 aria-label；每个 gridcell 内既有显示值的 `cell-display` 文本（保证 gridcell 的 textContent 即单元格值，供 `toHaveText` 断言），也含 aria-label 为坐标的 input（编辑面，聚焦时覆盖显示、失焦时透明）；选区为 anchor–active 矩形，区域内 gridcell aria-selected="true"。
- `frontend/src/csvExport.ts`：CSV 序列化（`escapeCsvField` / `cellExportValue` / `sheetToCsv`）。按网格实际结构 `rowCount × columnCount` 逐行逐列导出，空单元格保留为空字段，记录分隔 LF；含逗号/引号/换行的字段加引号并转义 `""`；公式单元格（以 `=` 开头）输出计算结果而非表达式。
- `frontend/src/sheetUtils.ts`：`nextSheetName(existingNames)` 返回第一个未占用的 `SheetN` 名（正整数序，从 Sheet1 起，名称先 trim 再比较，可复用改名后留下的空号），供 Add worksheet 命名。
- `frontend/src/formula.ts`：公式求值器（REQ-4-1-1 / REQ-4-2-1 / REQ-4-2-2）。支持算术 `+ - * / ^`、括号、一元负号、同工作表 A1 风格引用、聚合函数 `SUM`/`AVERAGE`/`COUNT`/`MIN`/`MAX`（连续区域 `A1:B2` 或参数列表）；函数名大小写不敏感；聚合函数忽略空单元格与非数值文本（COUNT 只计数值单元格，SUM/AVERAGE/MIN/MAX 只用数值单元格、不把空白当 0，MIN/MAX 无数值时返回 0、AVERAGE 无数值时显示 `#DIV/0!`、SUM/COUNT 无数值时返回 0）；普通算术中引用空单元格按 0 处理（使 `=C1*2` 在 C1 空时显示 0）。错误分类（REQ-4-2-2）：`evaluateFormula` 不再对公式错误抛异常，而是返回稳定可见令牌——除零（含 AVERAGE 无数值）返回 `#DIV/0!`、公式文本含 `#REF!`（结构变更/越界平移）返回 `#REF!`、未知函数返回 `#NAME?`、无法解析的表达式及对非数值文本做算术返回 `#ERROR!`；直接或间接循环引用返回 `#REF!`（求值沿引用链维护 visiting 栈，回到链上已有单元格即判循环，网格调用 `cellDisplayValue` 时以单元格自身坐标种子化栈）。错误令牌会沿依赖链传播（被引用公式求值为令牌时依赖方显示同一令牌），一个错误单元格不影响无关公式计算。供网格显示（`cellDisplayValue`）与 CSV 导出使用。
- `frontend/src/pivot.ts`：透视纯逻辑（REQ-5-3-1）——`nextPivotName`（首个未占用 PivotN）、`parseableNumber`、`headerTextsInRange`、`computePivot`（只读源表生成汇总 cells，见数据与接口约定的透视条目）。
- `frontend/src/rowColOps.ts`：行/列结构操作纯函数与验证规则（REQ-2-2-1/2-2-2/5-2-1）、旧式无 config 透视的范围调整（stale/adjustedRange/`refreshPivot`）、`parseRange/formatRange/isCoordInRange`、`validationErrorForInput`。
- 依赖重算（REQ-4-2-1）：公式结果不缓存，网格每次渲染按当前活动表 `cells` 即时递归求值，因此源值编辑、批量粘贴、区域移动（copy/cut 粘贴）与行/列插入删除成功后，直接与间接依赖公式自动按依赖顺序重算；结果随源值持久化，刷新/重开不显示变更前结果；公式栏始终显示单元格存储的原公式文本（结构变更后为调整后的公式）。求值只读活动工作表 `cells`，其他工作表的公式按各自表的值求值，不因本表编辑改变。
- `backend/csv.js`：RFC 4180 风格 CSV 解析器。`parseCsv(text)` 保持行/列顺序、保留空字段（含首/中/尾），支持引号内逗号、`""` 转义、引号内换行（原文保留）、\n/\r/\r\n 记录分隔；以引号开头但未闭合的字段抛出 `Invalid CSV file format. Import failed.`。另导出 `cellCoordinate(row, column)`（如 A1）。
- `frontend/src/api.ts`：同源相对路径 fetch 封装（GET /api/workbooks、POST /api/workbooks、POST /api/import-csv、GET/PUT /api/workbooks/:id）。

## 数据与接口约定

- 复制/剪切/粘贴（REQ-3-2-1 / REQ-4-1-2）：`frontend/src/internalClipboard.ts` 提供工作表级应用内剪贴板（`InternalClipboard { sheetId, kind:'copy'|'cut', anchor/active(规范化左上/右下), rows(2D 原值) }`，`setInternalClipboard/getInternalClipboard/clipboardRowsForSheet/clipboardTextForRows`）；`copyRange` 把当前选区（anchor–active 矩形）读入剪贴板，不修改任何单元格，best-effort 写 OS 剪贴板（grid onCopy/onCut 事件写 clipboardData，工具栏/菜单按钮用 navigator.clipboard）。粘贴优先使用同工作表（sheetId 匹配）的内部剪贴板，否则回退外部文本粘贴（REQ-3-1-2 路径）；跨工作表不转移。`pasteOps.applyClipboardPasteToSheet(sheet, startCoord, clipboard)` 先校验整个目标矩形（越界/验证失败整体拒绝返回原 cells），copy 按目标偏移翻译相对引用（`formula.translateFormulaRefs`，绝对引用 `$` 不变，移出网格变 `#REF!`），cut 在同一原子更新内先删源矩形再写目标（move 语义，公式不重写）；剪切动作本身不清源，只有粘贴成功后源才被清除。工具栏新增可访问名 `Copy`/`Cut`/`Paste` 按钮（`Workbook toolbar` 内，Export CSV 前）；单元格右键菜单含 `Copy`/`Cut`/`Paste` menuitem（右键在选区内的单元格保持选区，选区外折叠到该格；菜单容器 `onMouseDown` stopPropagation 避免点击菜单项冒泡到 gridcell 的 onActivate 折叠选区）。公式求值器支持 `$` 标记（`=$A$1` 按 A1 求值）。
  - 公式平移（REQ-4-1-2）：`formula.translateFormulaRefs(formula, rowOffset, colOffset, bounds?)` 按目标偏移改写相对引用，绝对引用（`$`）保持不变；引用移出网格（上/左边缘，或提供 `bounds`（目标表 rowCount/columnCount）时越过下/右边缘）改写为 `#REF!`，粘贴后公式栏显示调整后的原公式（如 `=#REF!*2`，纯引用公式显示 `=#REF!`），网格显示 `#REF!`；源公式与结果不变，目标结果随新引用重算并持久化。`pasteOps` 在 copy 翻译时传入目标表尺寸。REQ-4-1-2 场景镜像见 `frontend/src/FormulaCopy.test.tsx`。

- 撤销/重做（REQ-3-2-2）：`EditorPage` 持有会话级（不持久化）整簿快照栈 `undoStackRef`/`redoStackRef`；可撤销操作（单元格编辑、外部/内部剪贴板粘贴即范围移动、行/列插入删除）在改状态前把整份工作簿快照压入 undo 栈并清空 redo 栈。同一单元格的连续按键（同一编辑会话，`lastEditRef` 记录 {coord, after}，当次编辑前状态与上次编辑后状态引用相等即合并）只产生一条撤销记录，一次 Undo 恢复编辑会话前值。`handleUndo`/`handleRedo` 弹出快照、恢复该快照的活动表选择并整份持久化（撤销/重做后的状态刷新后可见）；工具栏提供可访问名 `Undo`/`Redo` 按钮（按栈空 disabled），Ctrl+Z/Ctrl+Y（window keydown，preventDefault）执行相同操作；撤销后的新修改清空 redo 栈（Redo 禁用、Ctrl+Y 无效果）。历史随 EditorPage 实例存在（路由按 workbookId key 挂载），天然按工作簿隔离；保存失败回滚时若 undo 栈顶等于回滚后的 committed 状态则弹出该过期条目。Escape 恢复（handleRevertCell）只清 redo 栈不入 undo 栈。

- 行/列结构操作（REQ-2-2-1 / REQ-2-2-2）：`frontend/src/rowColOps.ts` 提供纯函数 `insertRow/deleteRow/insertColumn/deleteColumn`（cells 整体平移、公式引用调整、验证规则范围平移/移除、rowCount/columnCount 更新）与整簿级 `workbookWithRowInsert/Delete`、`workbookWithColInsert/Delete`（仅活动表变更，其他工作表不变）。filterViews 名称型模型保持不变（继续作用于原数据区域）。删除行/列时公式引用被删行/列改写为 `#REF!`，公式求值器（`formula.ts` 的 `REF_ERROR`）将其作为显式错误显示；受影响公式在公式栏显示调整后的公式文本，网格显示计算结果。`adjustFormulaRefs`/`shiftRange` 的 change 参数为 `{ insertRow?, deleteRow?, insertColumn?, deleteColumn? }`（0 基索引）。
- 行号/列号菜单：行号 `rowheader` 的 accessible name 为十进制行号（aria-label 固定）；列头 `columnheader` 的 accessible name 为列字母（aria-label 固定）。右键行号或列头（或键盘 Enter/Space/ContextMenu）打开 `role=menu`，行菜单含 `menuitem` 命令 `Insert 1 row above` / `Insert 1 row below` / `Delete row`，列菜单含 `Insert 1 column left` / `Insert 1 column right` / `Delete column`（`data-row-menu` / `data-row-header`、`data-col-menu` / `data-col-header` 用于外点关闭判定）。
- 验证规则（REQ-5-2-1）：`ValidationRule` 扩展为 `{ id, range, type, values?, min?, max? }`，`type` 为 `dropdown`（`values` 为 trim 后允许值数组）或 `number`（`min/max`）。`validationErrorForInput` 是所有写路径（网格/公式栏/外部粘贴/内部剪贴板范围移动/行-列变化后）共用的校验入口：不在规则范围内的值、空值、`=` 开头的公式一律放行；dropdown 值不在允许列表返回 `Please select one of the following values: <逗号分隔允许值>`（输入按 trim 后比较）；number 越界/非数值返回 `numberValidationMessage(min,max)`——0-100 边界返回 `Please enter a number from 0 to 100`（REQ-3-1-2/3-2-1 与 REQ-5-2-1 持久化多格场景的逐字要求），其他范围返回 `Please enter a number between <minimum> and <maximum>`。行/列插入删除沿用 `shiftRange` 平移/移除规则范围，下拉按钮与数值限制随原约束单元格移动。`validationRuleForCoord(sheet, coord)` / `dropdownValuesForCoord(sheet, coord)` 供对话框预填与网格渲染。Data validation 区块显示 `range (type, values | min to max)`。
  - REQ-5-2-1 对话框：Data 菜单 `Data validation` menuitem 打开原生 dialog（可访问名 `Data validation`），含 label `Rule type` 的 select（option 可见名 `Dropdown`/`Number range`）、`Allowed values`（逗号分隔、逐项 trim、去空去重）、`Minimum`/`Maximum`、`Save`；选区（anchor–active 归一化）为规则范围。重开既有规则（`validationRuleForCoord` 按选区 anchor 命中）预填类型与参数并显示 `Delete rule` 按钮；保存以当前选区替换规则、删除移除约束，两者均走串行保存队列、成功后关闭对话框且不改单元格值，失败回滚最近成功提交并保持对话框显示错误。
  - 网格下拉按钮：受 dropdown 规则约束的 gridcell 内渲染可访问名 `Open dropdown for <坐标>` 的按钮（aria-haspopup=listbox、aria-expanded，mousedown stopPropagation），点击打开 role=listbox（aria-label `Options for <坐标>`），每项 role=option、可访问名为 trim 后允许值（aria-selected 标记当前值，支持方向键/Escape，点击写入该格并关闭）；与右键 cell-menu 的 `Options for <坐标>` 通过 role 区分。
- 过滤（REQ-5-1-2）：`FilterView` 扩展为 `{ id, name, range?, criteria? }`（兼容旧名称型视图），`FilterCriterion = { column(0 基表列索引), selectedValues? | condition? + value? }`，值筛选与条件互斥。`frontend/src/filter.ts` 提供纯函数：`activeFilterOf(sheet)`（活动过滤 = 最近创建的视图）、`distinctValuesInColumn`（范围内数据行去重非空值，首现顺序）、`filterMatchesRow`（各列 criterion 按 AND 组合；空数组 selectedValues 隐藏该列全部数据行）、`rowIsFilteredOut`（范围外与表头行恒可见）、`isFilterHeaderCell`、`matchesFilterCondition`。条件语义：`Text contains`（大小写不敏感子串）、`Greater than`（数值比较，非数值不匹配）、`Before`（Date.parse 日期比较，不可解析不匹配）、`Is empty`/`Is not empty`（无需 Value）。
  - 排序（REQ-5-1-1）：`frontend/src/sort.ts` 提供纯函数 `sortSheetRange(sheet, range, { column, order, hasHeader })`：在选区矩形内按列重排行记录（整行记录一起移动，范围外单元格不动），返回新 Sheet 或错误。排序键分类：空行恒排末尾（两向）、数值/可解析日期按数值比较且恒在文本前（两向）、文本按大小写不敏感字典序（原始文本作平局键）；稳定排序（相等键保留原相对顺序）。排序物理改写 range 内 cells 并随整簿 PUT 持久化，刷新后保持；filterViews/validationRules/selection 原样保留（继续作用于同一选区）。工具栏 Data 菜单新增 `Sort range` menuitem：打开原生 dialog（可访问名 `Sort range`），含 label `Sort by` 的 select（option 可访问名=选区首行各列文本，逐字）、label `Order` 的 select（option 可见名 `Ascending`/`Descending`）、`Data has header row` checkbox（默认勾选）、`Sort` 按钮（form submit）；排序失败（非法范围/列越界/保存失败）在对话框内 role=alert 显示错误且网格保持原序，保存成功关闭对话框。REQ-5-1-1 场景种子 `A1:C6`（headers `Region/Sales/Status`，行 `East/1200/Open`、`North/800/Closed`、`South/700/Open`）与 FilterRows/DataValidation 测试共用同一镜像工作簿（`SortRange.test.tsx` 另加 `D2='outside'` 与 `columnCount=4` 验证范围外不动）。
  - 工具栏新增可访问名 `Data` 的按钮（aria-haspopup=menu、aria-expanded，data-data-trigger），点击打开 role=menu（aria-label `Data menu`，data-data-menu）含 menuitem `Sort range` / `Create filter` / `Data validation` / `Clear filter`（data-data-menu-item，支持方向键/Home/End/Escape/外点关闭）。`Create filter` 以当前选区（anchor–active 归一化矩形，如 `A1:C6`）创建视图（名称 `Filter view N`）并设为活动过滤；`Clear filter` 移除活动（最后一个）视图，恢复全部源记录原顺序原值。`Sort range` 打开 REQ-5-1-1 的排序对话框，`Data validation` 打开 REQ-5-2-1 的验证规则对话框。
  - 活动过滤的表头行（range 首行）单元格内渲染 `Filter <header text>` 按钮（aria-label 逐字，data-header-filter=<0 基列索引>，z-index 高于 cell-input）；点击打开原生 dialog（aria-label `Filter <header text>`），内含值筛选区（`Clear selection` + 每源值一个 checkbox（以源值为可访问名）+ `Apply`）与条件区（label `Condition` 的 select（option 可见名 `Text contains`/`Greater than`/`Before`/`Is empty`/`Is not empty`）、label `Value` 的 textbox（Is empty/Is not empty 时隐藏）、`Apply`）；两个 `Apply` 分别提交 selectedValues / condition+value 到活动视图并持久化（提交后关闭对话框、焦点回到表头按钮）。
  - 行可见性：`WorksheetGrid` 对 `rowIsFilteredOut` 的行不渲染（行号跳变）；被隐藏行仅隐藏——CSV 导出（`sheetToCsv` 读全表）与透视仍包含范围内隐藏行；单元格、公式与验证行为不变。过滤视图随整簿 PUT 持久化，刷新/重开后保持。行/列结构操作沿用既有约定：filterViews 原样保留（名称型模型）。

Select a new field.` 并置 `fieldError=true`，数值错误→同文案）保留结果工作表旧汇总与源表。结果表上的 `Refresh pivot table` 按钮始终可用，源表 `Pivot table results` 区块仅在 stale 时显示该按钮；fieldError 文案按有无 `config` 区分。

- 编辑器保存链路：每次单元格编辑/切表/重命名/添加工作表即触发整份状态保存，队列串行化；保存失败回退到最近一次成功提交并显示错误（不产生部分记录）。重命名提交前客户端 trim，空名不发请求并在表单旁显示错误。

- REQ-2-1-4 删除工作表：工作表 tab 菜单（`Options for <name>`）在 `Rename` 后提供 `role=menuitem` 的 `Delete` 命令；点击时若整簿只剩 1 张表则不打开对话框、在 tab 栏下方以 role=alert 显示 `A workbook must contain at least one worksheet`；否则打开原生 dialog（可访问名 `Delete worksheet`，`aria-labelledby` h2），可见文本含目标表名（`Delete worksheet <name>? This cannot be undone.`），确认按钮 `Delete worksheet`（另有 `Cancel`）。确认时若目标表仍是某 pivot 的 `sheetId`（源表）则关闭对话框并在 tab 栏下方显示 `Please delete or rebuild dependent pivot tables first`，源数据与透视结果均不变；否则乐观删除：从 sheets 移除目标表、移除 `pivots` 中 `resultSheetId === 目标表` 的记录（源表不再受该透视约束）、删除的是活动表时激活相邻表（index 处取 remaining[min(index, len-1)]，即后一个或前一个）、清空 `editStartRef` 并恢复新活动表 selection（缺省 A1），走串行保存队列；保存失败经 `persist` 回滚（显示 `Save failed`，目标 tab 与网格保持）。`deleteSheetError` 在 `handleDeleteDialogClose` 中不清除（真实浏览器中 dialog close 事件异步触发，会在确认处理器之后清掉刚设置的拒绝文案），改由再次打开删除对话框、切表或添加工作表时清除。

## 已确认的注意事项

- 平台合同：`/health` 与 `/api/health` 返回 `{status:"ok"}`；`/` 提供 `frontend/dist`；未知路径（含 /favicon.ico）返回 404 且进程不退出；静态路径基于 `server.js` 自身位置解析。
- Vitest 配置 `fileParallelism:false`：规避 vitest 2.1.9 在 `--maxWorkers=1` 下 forks 池 minThreads/maxThreads 冲突。
- gridcell 可访问名即坐标，Playwright `getByRole('gridcell', {name:'A1'})` 需 exact 匹配，否则会命中 A10–A19 等同前缀坐标。
- gridcell 的 textContent 等于单元格显示值（`cell-display` span，CSS `visibility:hidden` 仅发生在聚焦编辑时，textContent 不受影响），`expect(gridcell).toHaveText(值)` 可直接断言；公式单元格显示计算结果（`cellDisplayValue`），错误公式显示稳定错误令牌（`#DIV/0!`/`#REF!`/`#NAME?`/`#ERROR!`），输入框与公式栏仍为原始公式文本；textbox 定位（`getByRole('textbox', {name:'A2'})`）同样需 exact 匹配以避开 A20 等同前缀坐标。
