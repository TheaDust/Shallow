# ARCHITECTURE.md

## Entry

- Frontend: `frontend/src/main.tsx` → `App.tsx` (hash-routed SPA via `src/lib/hash-route.ts`).
  Routes: `#/` (landing or workspace), `#/signin`, `#/signup`, `#/forgot-password`, `#/settings`, `#/settings/password-and-authentication`, `#/organizations`, `#/organizations/new`, `#/repositories/new`, `#/orgs/:org[/repositories|/people|/teams|/teams/new]`, `#/orgs/:org/teams/:team[/members|/settings]`, `#/search?q=`, `#/repos/:owner/:name[/settings[/access|/branches]|/tree|/blob|/commits|/commit/:commitId|/compare|/search|/new|/edit|/issues|/issues/new|/issues/:number|/pulls|/pulls/new|/pulls/:number]`. Unknown hash paths render home; settings routes render home (anonymous landing) without session.
- The app top bar renders for all users: a Home link, a global search form (`role=search`, `searchbox` `Search`) submitting to `#/search?q=`, and the account menu when authenticated.
- Global search results (`features/search/SearchResultsPage.tsx`) use a type-filter tablist (`Repositories` default; Code/Issues/Pull requests/Users tabs show `No results`); result links are named the repository name (`owner/name`) with description/visibility/update-time.
- Organization, team and repository pages live in `frontend/src/features/organizations/` (pages + `api.ts`); org/team nav entries are links styled as tabs. The org overview heading is the display name (e.g. `Acme Demo`); repository and team headings use the identifier. `PeopleTab.tsx` add-member form (`Username or email` + `Role` combobox), per-member `Member menu <username>` (`Remove from organization` + `Remove`); Owner-only. `ManageAccessPage.tsx`: grants as table rows (`Role` select + `Save`), `Role` combobox popover.
- Repository overview (`RepositoryPage.tsx`): `owner/name` heading, Public/Private marker, default branch, description, fork-source, root file list, Code/Issues/Pull requests nav (`RepoNav.tsx`), `Commits` link, admin `Settings` link, clone `Code` button, `Fork` button. `CodePage.tsx`/`BlobPage.tsx` serve tree/file via `/contents`; Code adds `Commits` link+count, `Search` searchbox, `Add file` menu (`Create new file`). `BranchSelector.tsx`: `Branch <name>` button → `Find branch` textbox + `role=option` list (aria-selected), writable users get `Create branch: <name>`. `BranchesPage.tsx`: `Default branch` select + `Update` → `Confirm` dialog; admin-only protection rules (`Add branch protection rule`: `Branch name pattern`, `Require 1 approval`, `Require status check test`).
- Repository creation (`NewRepositoryPage.tsx`, `#/repositories/new`): labels `Owner`/`Repository name`/`Description`, Public/Private radios, `Add a README file` checkbox, `Create repository`; Owner select = orgs where user is Owner. Settings (`RepositorySettingsPage.tsx`): General + Manage access; admin-only `Change visibility` dialog (`Confirm visibility`).
- Issues (`frontend/src/features/issues/`): `IssuesPage.tsx` (list + filters), `IssueDetailPage.tsx`, `NewIssuePage.tsx`, `ReactionMenu.tsx`, `MetadataPicker.tsx`, `RepoNav.tsx`. List keeps Open/Closed, `Search issues` + `Label` in hash; rows `role=row` (number + title link, status, author, labels, time); `New issue` for Write+; Detail `#<number>`, `h1`=title, `Assignees`/`Labels`/`Milestone`, `Comments`+`Activity`, `Close issue`/`Reopen issue` (Triage+).
- Pull requests (`frontend/src/features/pulls/`): `PullRequestsPage.tsx` (rows: title link/status/branches/author; `New pull request` for Write+; status/author/`Review status` hash filters), `PullRequestNewPage.tsx` (`#/pulls/new`: `base`/`compare` selects, `Compare changes`/`No changes`/`Commit summary`, `Create pull request`/`Create draft pull request` forms), `PullRequestDetailPage.tsx` (`h1`=title, status incl. `Draft`, tabs `Conversation`/`Commits`/`Files changed`/`Checks`, `Ready for review` → `Confirm` dialog, `Close`/`Reopen`, `Reviewers`, Checks; `Review changes` on Files changed → `ReviewChangesForm.tsx` (`Summary` + radios `Comment`/`Approve`/`Request changes` + `Submit review`); review cards (`Approved`/`Changes requested`/`Commented` + explanation + time) in Conversation + sidebar `Review summary`; `DiffView.tsx` per-line `Add comment` + `Comment` editor (`Add single comment`/`Start a review`), blocks (`Pending review`/`Outdated`), pending author-only; `MergeBox.tsx` `Merge pull request` + `Confirm merge` dialog lists conditions, blocked PRs keep disabled button + reasons).
- Backend: `backend/src/server.mjs` (zero-dep `node:http`). Reads `PORT` (default 3000) plus platform extra ports (`platform-ports.json`, skipped when `ARC_EXTRA_PORTS=0`); serves `frontend/dist` at `/`; `/health` + `/api/health`; unknown paths/APIs return 404. Data dir: `SHALLOW_DATA_DIR`, JSON `state.json` via `createJsonStore` (atomic writes, serialized queue). Route modules: `routes/issues.mjs`, `routes/pulls.mjs`.

## Shared interfaces

- `frontend/src/lib/api.ts`: `apiRequest` (same-origin fetch, JSON, throws `ApiError` with `status`/`body`).
- `frontend/src/ui/`: Button, Dialog, FormField, Menu, Tabs, Combobox, Toast. Dialog is `<dialog>`-based (modal, inert background).
- `frontend/src/features/auth/api.ts`: `fetchSession` GET `/api/session`; `registerAccount` POST `/api/register` (422 field `errors`); `signIn` POST `/api/signin` (401 `Invalid credentials`); `signOut` POST `/api/signout`; `requestPasswordReset`/`resetPassword` POST `/api/recovery/request|reset`; `changePassword` POST `/api/password/change`.
- `frontend/src/features/auth/session.tsx`: `SessionProvider`/`useSession` — `loading | anonymous | authenticated{account}`; `refreshSession()` re-reads `/api/session`.

## Domain (backend)

- `backend/src/domain/organizations.mjs`: store-backed operations on `{ organizations, memberships, teams, teamMembers, repositories, grants }`. Exports `effectiveRole(state, repo, accountId)` and `repositoryAccessible` (public or effective role) for reuse.
  - Organization: `{ id(=identifier), displayName, createdAt }`; membership `{ orgId, accountId, role: "member"|"owner", createdAt }` keyed `orgId:accountId`. Membership does not grant private-repo access.
  - `addMember` (by username/verified email, rejects unknown/duplicate/invalid role); `removeMember` deletes membership + team memberships + direct grants, keeps teams/team grants/account/personal repos, rejects removing the last Owner.
  - Team: `{ id(orgId:name), orgId, name, description, parentId, createdBy, createdAt }`, name 1–50 `^[a-z0-9]+(-[a-z0-9]+)*$`, unique per org, parent in same org, cycles rejected. Membership keyed `teamId:accountId`; hierarchy does not propagate grants.
  - Repository: `{ id(ownerId:name), ownerType, ownerId, name, description, visibility, defaultBranch, createdAt, updatedAt, createdBy?, forkSourceId?, ... }`, name 1–100 `^[a-z0-9][a-z0-9._-]*$`, unique per namespace. Creation requires self (personal) or org Owner; `initialize: true` adds branch/README/`Initial commit`. Visibility change requires org Owner or repo Admin. Forks require Read+ source + creation permission, copy git records, store `forkSourceId`.
  - Git: `state.git[repoId] = { branches: {name: commitId}, commits: {id: {id, message, author, createdAt, parentId, changes: [{path, additions, deletions, oldContent, newContent}]}}, files: {branch: {path: {content, commitId}}}, protectedBranches }`; `snapshotAt`/`diffLines` derive revisions. Branch name 1–255 `^[A-Za-z0-9._/-]+$` (`Invalid branch`). `/contents?branch=&path=` serves dir/file; `getRepository` includes default-branch root files + `forkSource`. `docs/guide.md` not pre-seeded (REQ-4-4); read-only nested file `src/search.ts`.
  - Grant: `{ id(repoId:subjectType:subjectId), orgId, repoId, subjectType, subjectId, role, grantedBy, createdAt }` — one grant per subject+repository (upsert replaces). Effective role = max(org Owner→Admin, direct member grant, direct team grants); private repos require an effective role; personal repo owner is Admin.
  - Server routes: org CRUD/people/teams (Owner gates), `GET/PATCH /api/repositories/:owner/:name`, access grants (org Owner or repo Admin), `/contents`, `/forks`, `/branches`, `/commits` (+`/:commitId`), `/compare`, `/search/code`, `/search/repositories`, `/api/repositories`. `POST .../commits` (Write+) atomic, messages 1–72. `PATCH .../default-branch` (Admin) stores `defaultBranchChangedBy/At`.
- `backend/src/domain/issues.mjs`: store-backed operations on `{ issues, labels, milestones, timelines, comments, reactions }` keyed per repo/issue.
  - Issue: `{ id(repoId:number), repoId, number, title, description, author, status: "open"|"closed", assignees[], labels[], milestone, createdAt, updatedAt }`; numbers repo-scoped, allocated atomically (max+1), failures never allocate. Content ops (create/edit/comment) require Write/Maintain/Admin (org Owner→Admin); view requires `repositoryAccessible`; reactions any signed-in viewer.
  - Timeline: append-only `state.timelines[repoId:number]` entries (`id, type, author, createdAt` + entry fields); comments stored via `commentId`; reactions `state.reactions[key][targetType:targetId][reaction] = [usernames]` (toggle per user/target/reaction).
  - Validation: title trimmed 1–256 (`Title is required`/`Title must be at most 256 characters`); description ≤65536; comment trimmed 1–65536.
  - Metadata/status ops (Triage/Maintain/Admin, `canManageIssue`): `toggleAssignee` (target role ≥ Triage), `toggleLabel` (`Label does not exist in this repository`), `setMilestone` (repo id or `None`), `setIssueStatus` (`Status is invalid`; same-status no-ops). `getIssue` returns `labels`/`milestones`/`assignableMembers` + `issue`/`myRole`.
  - Routes: `GET/POST .../issues`, `GET .../issues/:number`, `PATCH .../issues/:number/title|description|assignees|labels|milestone|status`, `POST .../issues/:number/comments|reactions`.
- `backend/src/domain/pulls.mjs`: store-backed PR operations on `{ pullRequests, pullRequestTimelines, pullRequestComments, pullRequestReviews, pullRequestReviewers, pullRequestChecks, pullRequestInlineComments }` keyed per repo/PR; numbers repo-scoped, allocated atomically.
  - PR `{ id(repoId:number), repoId, number, title, description, author, status: "draft"|"open"|"closed"|"merged", baseBranch, compareBranch, baseCommit, compareCommit, createdAt, updatedAt, mergedBy?/mergedAt?/mergeCommitId? }`; the current compare commit derives from the compare-branch head at read time; new compare commits restart checks as pending, old records stay on their own commit. Checks per compare commit: `state.pullRequestChecks[prKey][commitId].test = { status, setter, setAt }` (repo Admin only). Review decisions feed eligibility: latest per reviewer per current commit; stale otherwise; author never satisfies approval; any Request changes blocks.
  - `createPullRequest` accepts `draft`; `readyForReview` (author/Maintain/Admin/Owner) Draft→Open + `ready-for-review` timeline entry; `addInlineComment` (Write/Maintain/Admin, not author, Open only) stores `{ prKey, path, line(1-based diff position), commitId, author, body, state: published|pending, createdAt }`; published become `outdated` on compare-commit move, pending stay pending. `submitPullRequestReview` (`pull-reviews.mjs`; same roles, Open only) stores `{ prKey, reviewer, commitId(current), decision, explanation, createdAt }`, appends `review` timeline entry, publishes reviewer's pending inline comments. List summaries include `reviews` + `reviewRequested`.
  - Merge eligibility returns `{ eligible, reasons, conditions }` (`No merge conflicts`, `No valid Request changes`, per enabled rule `1 approval`/`Status check test is success`): conflicts → `Merge conflicts must be resolved`; blocking requests → `Requested changes must be resolved`; `requireApproval` → `Review required by branch protection`; `requireCheck` → `Required status check test must be successful`. Merge (Maintain/Admin/Owner) creates a merge commit, sets Merged (terminal); close/reopen (author/Maintain/Admin/Owner) never touches branches; reviewer requests need Write+ candidates.
  - Protection rules live in `state.git[repoId].protectedBranches[branch] = { branch, requireApproval, requireCheck, createdBy, createdAt, updatedAt }`; truthiness blocks direct commits. Admin-only `GET/POST .../protection-rules`.
  - Routes: `GET/POST .../pulls`, `GET .../pulls/comparison` (Write+), `GET .../pulls/:number`, `PATCH .../pulls/:number/status`, `POST .../pulls/:number/ready-for-review`, `POST .../pulls/:number/inline-comments`, `POST .../pulls/:number/reviews`, `POST .../pulls/:number/reviewers`, `DELETE .../pulls/:number/reviewers/:username`, `POST .../pulls/:number/checks`, `POST .../pulls/:number/merge`, `GET/POST .../protection-rules`.
- `backend/src/domain/accounts.mjs`: `{ accounts, sessions }`. Account `{ id(=username), username, email, emailVerified, password "<salt>:<scrypt>", status, createdAt }`; session `{ id: uuid, accountId, status, createdAt }`, cookie `session` (HttpOnly, SameSite=Lax, 30d). `changePassword` session-scoped; registration validates username/email/password/confirm/terms atomically; recovery uses fixed code `123456`.
- `backend/src/lib/`: `validation.mjs`, `passwords.mjs` (scrypt), `json-store.mjs`, `http.mjs`.

## Conventions

- Session auth: protected requests resolve the current user via `/api/session` (cookie `session`); frontend hides nothing server-side.
- Visibility: public repos visible to all; private repos only with an effective role. Permissions are per-operation (explicit role lists), not a cumulative ladder.
- Filters/selections live in the hash query; filtering never writes data; search-as-you-type reads the live hash.
- No page shows a full password; password inputs clear after failed submits; other inputs retained.
- Registration success → `#/signin?registered=1`; sign-in → `#/`; sign-out → `#/` anonymous landing.
- Security page change-password form; success keeps it + `Password updated` (role=status). Account menu: `Your organizations`, `Settings`, `Sign out`.
