# Architecture

## Entry points (frontend, hand-rolled hash routing)

- `#/` — workbook home page (`pages/HomePage.tsx`).
- `#/new` — blank workbook creation page (`pages/CreatePage.tsx`).
- `#/workbook/:id` — workbook editor (`pages/EditorPage.tsx`); directly accessible and refreshable, loads the workbook by id from the backend.

Routing lives in `App.tsx` via `lib/hash-route.ts` (`useHashLocation`, `navigate`, `makeHash`).

## Backend

- Zero-dependency Node HTTP; `server.mjs` serves `frontend/dist`, `/health` + `/api/health`, and `/api/*` (unknown API → 404, unknown static → 404). Listens on `PORT` plus `platform-ports.json` extra ports (skipped when `ARC_EXTRA_PORTS=0`).
- Data dir: `SHALLOW_DATA_DIR` (default `backend/../../data`). Atomic JSON store in `lib/json-store.mjs`.
- API (routes in `api.mjs`, domain logic in `workbook-service.mjs`):
  - `GET /api/workbooks`, `POST /api/workbooks` (blank), `POST /api/workbooks/import` (`{fileName, csv}`), `GET /api/workbooks/:id`, `POST /api/workbooks/:id/rename` (`{name}`), `POST /api/workbooks/:id/active-sheet` (`{sheetId}`), `GET /api/workbooks/:id/export`.
  - `POST /api/workbooks/:id/sheets` (add worksheet), `POST /api/workbooks/:id/sheets/:sheetId/rename` (`{name}`), `POST /api/workbooks/:id/sheets/:sheetId/delete` (deletes a worksheet and everything it owns; rejects `A workbook must contain at least one worksheet` when it is the last sheet and `Please delete or rebuild dependent pivot tables first` when another sheet's pivot reads it as its source; adjacent sheet becomes active; atomic), `POST /api/workbooks/:id/sheets/:sheetId/structure` (`{op, index}` with ops `insert-row-above|below`, `delete-row`, `insert-column-left|right`, `delete-column`; 1-based index). All return `{workbook}`.
  - `POST /api/workbooks/:id/sheets/:sheetId/cells` (`{cells: Record<coord, string>}`; `"=…"` values become formulas; atomic write + recalc; validation failure → 400, store unchanged).
  - `POST /api/workbooks/:id/sheets/:sheetId/range-transfer` (`{source, target, mode: "copy"|"cut"}`; `target.start` is the paste anchor; formulas adjust by offset; cut clears source atomically).
  - `POST /api/workbooks/:id/sheets/:sheetId/restore` (`{sheet}` snapshot; atomically replaces the worksheet's cells/rules/filters/pivot and recalculates; used by undo/redo so restored states persist).
  - `POST /api/workbooks/:id/sheets/:sheetId/selection` (`{selection: {start,end} | null}`; persists a worksheet's complete rectangle).
  - `POST /api/workbooks/:id/sheets/:sheetId/filter` (`{range, conditions?}` upserts the sheet's filter view; `{clear: true}` removes it). Conditions are `{column, mode: "values", values[]}` or `{column, mode: "condition", condition: "text-contains"|"greater-than"|"before"|"is-empty"|"is-not-empty", value?}` (columns are 1-based absolute).
  - `POST /api/workbooks/:id/sheets/:sheetId/validation` (`{range, rule: {type: "dropdown", allowedValues[]}}` or `{range, rule: {type: "number", min, max}}` upserts a rule, replacing every stored rule intersecting the range; `{deleteRuleId}` removes one; never rewrites existing cell values; atomic).
  - `POST /api/workbooks/:id/sheets/:sheetId/sort` (`{range, sortBy, order: "ascending"|"descending", hasHeaderRow}`; `sortBy` is a 1-based absolute column inside the range; cells move only inside the rectangle, formulas move as-is and recalculate; blank rows sort last in both directions; stable; atomic).
  - `POST /api/workbooks/:id/pivots` (`{sourceSheetId, sourceRange}`) creates a pivot-result worksheet with the first unused `PivotN` name (active) and an empty field layout; `POST /api/workbooks/:id/sheets/:sheetId/pivot` (`{rowField, columnField|null, valueField, summarizeBy}`) resolves headers in the source range's header row, computes the summary into the pivot sheet's cells (clearing the previous `resultRange`), and throws `Pivot field is no longer available. Select a new field.` / `Value field requires numeric values` atomically; `POST /api/workbooks/:id/sheets/:sheetId/pivot-refresh` recomputes from the stored config (errors leave the store unchanged).
- CSV parse/serialize in `lib/csv.mjs` (RFC 4180; a field starting with `"` without a closing quote is invalid → `Invalid CSV file format. Import failed.`).
- Structure ops are atomic (single `store.update`): cells shift, formula references are rewritten (`lib/refs.mjs`; sheet-prefixed refs untouched; unpreservable refs → `#REF!`, value set to `#REF!`), validation/filter ranges shift, filter condition columns shift (deleted-column conditions are dropped), pivot configs referencing the changed sheet as their source shift their source range/field columns and mark `broken` when a field column is deleted; the pivot sheet's own structure op shifts only its cached `resultRange`. Deleted-row/column rules are removed.
- Formulas: `lib/formula.mjs` parses/evaluates `=` expressions (arithmetic, refs, ranges, SUM/AVERAGE/MIN/MAX/COUNT/COUNTA, sheet-prefixed refs; function names and column letters case-insensitive, `$`-absolute refs kept) and exports `adjustFormulaForCopy` (relative refs shift; out-of-bounds refs become `#REF!`). `recalculateWorkbook` (in `workbook-service.mjs`) recomputes every formula cell to a fixpoint after each cell write, structure change, paste or restore; it pins direct/indirect circular references to `#REF!` and renders unparseable stored formulas as `#ERROR!` (malformed formulas are accepted and stored so the formula bar keeps the submitted expression). Stable error values: `#DIV/0!`, `#REF!` (invalid/missing refs, cycles, broken refs after structure ops/copy), `#NAME?` (unsupported function), `#ERROR!` (malformed). Aggregates ignore empty cells; COUNT counts only numeric cells; SUM/AVERAGE/MIN/MAX use only numeric cells; empty refs behave as 0 in arithmetic.
- Validation: a sheet's `validationRules` entries are `{id, type: "dropdown", range, allowedValues[]}` or `{id, type: "number", range, min, max}` (legacy `criteria`/`validationType`/`ruleType` and `numeric` accepted). Writes through the grid, formula bar, paste or range move are validated atomically against every rule whose range contains the written cell: dropdown rejects values outside the trimmed `allowedValues` with `Please select one of the following values: <comma-separated allowed values>`, number rules reject non-numeric or out-of-bounds values with `Please enter a number between <min> and <max>`; the 0-to-100 boundary rule keeps its historical `Please enter a number from 0 to 100` wording. Empty values are always allowed; rules move with structure ops and stay active after refresh; creating a rule never rewrites existing cell values.

## Shared conventions

- Workbook model: `{ id, name, createdAt, updatedAt, activeSheetId, sheets: [{ id, name, cells: Record<coordinate, { value, formula? }>, validationRules?, filterViews?, pivot?, selection? }] }`. Cells keyed by coordinate (e.g. `A1`); `value` is the displayed/calculated value, `formula` the raw expression (formula bar shows `formula ?? value`; export uses `value`). `selection` is the persisted rectangle `{start, end}` of the most recent successful selection (per sheet). `filterViews` holds one view `{id, range, conditions}` per sheet. `pivot` (on the result sheet) holds `{sourceSheetId, sourceRange, rowField/rowFieldColumn, columnField|null/columnFieldColumn|null, valueField/valueFieldColumn, summarizeBy, resultRange, broken?, lastError?}`; the summary is written into the result sheet's cells.
- Coordinate helpers: `columnLabel`/`cellCoordinate`/`parseCoordinate`/`normalizeRange`/`rangeContains` in `backend/src/lib/refs.mjs` and `frontend/src/domain/grid.ts` (the frontend mirrors them plus `normalizeSelection`/`selectionContains`/`clampSelection`/`singleCellSelection`); grid renders ≥ 20 rows × 8 columns from `gridDimensions`.
- Editor accessibility contract: tab bar (`components/WorksheetTabBar.tsx`) renders `role=tablist` with `role=tab`/`aria-selected`, per-tab `Worksheet options for <name>` menu buttons (menuitem commands `Rename`/`Delete`), and an `Add worksheet` button; active grid is `role=grid`, `aria-label="Worksheet grid"`, `aria-multiselectable="true"`; cells are `role=gridcell` with coordinate accessible names and `aria-selected` per rectangle (true inside, false outside); row numbers are `role=rowheader`, column headers `role=columnheader`; formula bar is `aria-label="Formula bar"`, the active-cell indicator is `aria-label="Active cell"`. Right-clicking a cell opens a context menu with `Copy`/`Cut`/`Paste` menuitems; row/column headers open structure menus (`components/GridContextMenu.tsx`). The toolbar also has a `Data` button (`components/Menu` primitive) with menuitems `Create filter`, `Sort range`, `Data validation`, `Create pivot table`, `Clear filter`.
- Filtering (`domain/filter.ts`): `buildHiddenRows` hides data rows inside the filter range that fail any column condition (AND across columns); the header row and rows outside the range stay visible; rows are hidden only (never deleted/reordered). Header cells of the active filter view render `Filter <header text>` buttons opening the `Filter <header text>` dialog (`components/FilterDialog.tsx`): a values section (distinct source values as checkboxes, `Clear selection`, `Apply`) and a condition section (`Condition` combo with `Text contains`/`Greater than`/`Before`/`Is empty`/`Is not empty`, `Value` text box disabled for the empty conditions, `Apply`). `Clear filter` removes the view; CSV export reads all cells so hidden rows are included.
- Data validation & sort dialogs: `components/DataValidationDialog.tsx` (dialog name `Data validation`, `Rule type` combo `Dropdown`/`Number range`, `Allowed values`/`Minimum`/`Maximum` text boxes, `Save`, `Delete rule` when a rule covers the selection; `domain/validation.ts` provides `ruleForSelection`, `parseAllowedValues`, `dropdownRuleAt`) and `components/SortRangeDialog.tsx` (dialog name `Sort range`, `Sort by` combo with the range's header texts, `Order` `Ascending`/`Descending`, `Data has header row` checkbox, `Sort`); both are reached from the `Data` menu, save/delete through their own API calls, and the editor records undo snapshots captured when each dialog opens.
- Dropdown cells: a cell inside a dropdown rule renders a button with accessible name `Open dropdown for <coordinate>` opening a `role=listbox` popup whose options use `role=option` and the trimmed allowed value as accessible name; selecting an option commits the value through the normal cells API.
- Pivot editor (`components/PivotEditor.tsx`): a `Pivot table editor` region (role=region) shown on pivot result sheets with `Rows`/`Columns`/`Values` combo boxes (options = source header texts, placeholder `(None)`) and `Summarize by` (SUM/COUNT/AVERAGE) plus `Apply` and `Refresh pivot table`. No column field: `A1` row-field name, `B1` `<SUM of value field>`, rows by first appearance, final `Grand Total`. With a column field: column values from `B1` onward, `Grand Total` final column and row. SUM/AVERAGE aggregate parseable numbers; COUNT counts non-empty value fields (0 when none).
- Editing: double-click a grid cell opens an inline text box `aria-label="Edit <coordinate>"`; Enter commits, Escape cancels, blur commits (clicking another cell). Formula bar commits on Enter and on blur; Escape cancels. Commits call the cells API; failures keep the last successful content and show an `role=alert` error.
- Range transfer: `domain/clipboard.ts` holds the in-app clipboard buffer (`{sheetId, source, mode}`) and TSV parse/serialize; copy/cut set the buffer (and attempt `navigator.clipboard.writeText`), Ctrl+C/Ctrl+X/Ctrl+V and the context menu paste into the selection anchor; cut clears the source only after a successful paste; pasting across worksheets is rejected (`Paste is only supported within the same worksheet`). The grid's `paste` event pastes external TSV text into the anchor cell; the context-menu `Paste` falls back to `navigator.clipboard.readText()` when there is no in-app buffer, so it pastes the same external clipboard content Ctrl+V would paste.
- Undo/redo (`domain/history.ts`): session-scoped stacks keyed by workbook id (`{undo, redo}` per workbook; a reload clears them). Each successful cell edit, bulk paste, range transfer, row/column structure op, validation-rule save/delete and range sort records `{sheetId, before, after}` snapshots (cells incl. formulas, validation rules, filter views, pivot). Toolbar buttons `Undo`/`Redo` plus Ctrl+Z/Ctrl+Y restore via the `restore` API (undo restores `before`, redo `after`); a new modification after an undo clears the redo branch. Failed operations never record entries; failed restores push the entry back for retry. Undo/redo state persists after refresh because restore writes the snapshot to the store.
- Selection persistence: every selection change is saved immediately via the selection API (at most one in-flight request per sheet; newer rectangles coalesce behind it, and the save uses `keepalive` so it survives an immediate reload); per-sheet rectangles are restored after refresh and preserved across tab switches (`EditorPage` keeps `sheetSelectionsRef`). Tab switches call the active-sheet API; a failed switch reverts to the previous tab, its confirmed selection, formula bar and an error, leaving the source sheet untouched.
- Rename dialogs: workbook rename (`Rename workbook` / `Workbook name cannot be empty`), worksheet rename via tab menu (`Rename worksheet` dialog, `Worksheet name` label; server messages `Worksheet name cannot be empty`, `Worksheet name already exists`). Worksheet names must be unique per workbook; new sheets use the first unused `SheetN`.
- Seed (seeded only when the store file is absent): workbook `Q3 Sales` (id `wb-seed-q3`) with `Sheet1` cells `A1:C4` = headers `Region/Sales/Status` and rows `East/1200/Open`, `North/800/Closed`, `South/700/Open` (the evaluation seed declares the used range `A1:C6`; rows 5-6 are empty), plus blank `Sheet2`; user changes persist.
- Export filename: `<workbook name>.csv`; export reads only the active worksheet's used range.
