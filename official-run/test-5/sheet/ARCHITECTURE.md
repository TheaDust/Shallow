# Architecture

## Runtime contract
- `frontend/` React 18 + Vite + TS (hash routing, same-origin `/api/...` only). Build: `npm --prefix frontend run build` (runs `tsc --noEmit` then vite). `backend/` zero-dependency Node HTTP; start: `npm --prefix backend run start`.
- `backend/src/server.mjs` listens on `PORT` (default 3000) plus every port in `backend/src/platform-ports.json` (skipped when `ARC_EXTRA_PORTS=0`); each port gets its own `createServer(handler)` bound to `0.0.0.0`.
- `backend/src/app.mjs` `createRequestHandler({store, staticRoot})` is the single handler: `/health` + `/api/health` → `{ok:true}`; `/api/workbooks*` → `backend/src/api.mjs`; everything else → static files from `frontend/dist` (resolved from the module path, not cwd). Unknown paths/APIs (incl. `/favicon.ico`) → 404 JSON, process stays up.
- Persistence: `createJsonStore(<SHALLOW_DATA_DIR>/workbook-store.json, createSeedState())`; `SHALLOW_DATA_DIR` unset falls back to `backend/.data`. The seed applies only when the store file does not exist, so user changes survive restarts; one atomic JSON write per mutation (temp+rename), a failed mutation writes nothing.

## Hash routes (frontend/src/App.tsx)
- `#/` workbook home page (`WorkbookHomePage`); `#/workbooks/new` creation page, submit button `Create`; `#/workbooks/<workbookId>` editor (`WorkbookEditorPage`), direct open + refresh restore that workbook. Unknown entries fall back to the home page.

## HTTP API (`backend/src/api.mjs`)
Every workbook response is `{workbook}` from `toWorkbookPayload(workbook, {canUndo, canRedo})`: stored fields + derived `values`/`hiddenRows` per worksheet + the undo/redo availability of the running session. Errors are `{error}` with 400/404/405.
- `GET /api/workbooks` → `{workbooks:[{id,name,createdAt,updatedAt}]}` (updatedAt desc). `POST /api/workbooks` `{name}` → 201 (blank → `Untitled workbook`, >200 chars → 400). `POST /api/workbooks/import` `{fileName,content}` → 201 (name = file name minus `.csv`; parse failure → 400 `Invalid CSV file format. Import failed.`). `GET /api/workbooks/:id` → 200 | 404 `Workbook not found`.
- `PATCH /api/workbooks/:id` `{name?}`/`{activeWorksheetId?}` → 200 (empty body → 400 `Nothing to update`; blank/over-long name → 400 `Workbook name cannot be empty`/`Workbook name is too long`; unknown worksheet → 400 `Unknown worksheet`). `POST .../worksheets` → 201 blank `SheetN`, activated. `POST .../undo`/`.../redo` → 200 | 400 `Nothing to undo`/`Nothing to redo`. A rename refreshes `updatedAt`, a view-state patch does not.- `GET .../worksheets/:wsId/export` → 200 `text/csv; charset=utf-8` + `Content-Disposition` (`<workbook> - <worksheet>.csv`); read-only; unknown ids → 404.
- `PATCH .../worksheets/:wsId` `{activeCell?}`/`{selectionFocus?}`/`{name?}`/`{validations?}`/`{filter?}` → 200; bad address → 400 `Invalid cell address`, empty body → 400 `Nothing to update`, `activeCell` without `selectionFocus` collapses the rectangle, invalid rule → 400 `Invalid validation rule`, unenforceable filter → 400 `Invalid filter` (nothing stored), blank/duplicate name → 400 `Worksheet name cannot be empty`/`Worksheet name already exists`. Rename, rule and filter changes refresh `updatedAt` (a filter change is also recorded in the undo history); selection-only patches do neither.
- `POST .../worksheets/:wsId/cells` `{updates:{"D1":"East","E1":""}}` → 200: one atomic write of raw cell texts (`""` clears); addresses, values and rules are checked first, so a rejected write (400 `Invalid cell address`/`Invalid cell value`/rule message) leaves the worksheet untouched. Recorded in the undo history.
- `POST .../worksheets/:wsId/rows` `{op:"insert-row-above"|"insert-row-below"|"delete-row", row}` and `.../columns` `{op:"insert-column-left"|"insert-column-right"|"delete-column", column}` → 200; unknown op → 400 `Unknown row operation`/`Unknown column operation`, out-of-range → 400 `Invalid row number`/`Invalid column`. Recorded in the undo history.
- `POST .../worksheets/:wsId/range-transfer` `{mode:"copy"|"cut", source, target}` (`"D1:E2"` or `{start,end}`) → 200: `transferUpdates` builds one `{address:text}` map (target rectangle = source size at the target's top-left corner, copied formulas offset, cut source cleared except cells the target covers) and applies it through the same atomic write, so a rule violation keeps source, target and dependents as they were. Unknown mode → 400 `Unknown transfer mode`, bad/oversized range → 400 `Invalid range`/`Cell is outside the worksheet bounds`.
## Data model (`backend/src/domain/workbooks.mjs`)
```
state            = { workbooks: Workbook[] }
Workbook         = { id, name, createdAt, updatedAt, activeWorksheetId, worksheets: Worksheet[] }
Worksheet        = { id, name, activeCell, selectionFocus, cells: Record<"A1", string>, validations: ValidationRule[], filter: WorksheetFilter|null }
ValidationRule   = { id, range:{start,end}, type:"number-between", min, max, message }
                 | { id, range:{start,end}, type:"dropdown", values: string[], message }
WorksheetFilter  = { range:{start,end}, columns: Record<"A", {kind:"values",values:string[]}|{kind:"condition",operator,value}> }
Worksheet (API)  = Worksheet + { values, hiddenRows: number[] }
```
`cells` stores sparse raw cell text by coordinate (`=...` is a formula); `activeCell`/`selectionFocus` are the two corners of the selection rectangle, so a refresh or a worksheet switch restores the whole rectangle. `coordinates.mjs` (server) and `coordinates.ts`/`selection.ts`/`gridEditing.ts` (client) share the `A1` ↔ `{column,row}` rules.

Display values are derived, never stored: `formula.mjs` `worksheetValues(worksheet)` returns the displayed text of every non-empty cell — ordinary cells keep the exact typed text, formula cells the result or an error code (`#ERROR!`, `#DIV/0!`, `#VALUE!`, `#NAME?`, `#REF!`). It evaluates `+ - * / ^`, parentheses, unary minus, A1 refs and SUM/AVERAGE/COUNT/MIN/MAX, memoised per call so a committed source updates direct and indirect dependents; refs outside the 20x40 grid and circular chains return `#REF!`. `worksheetToRows` (CSV export) reuses the values.

Writes are gated by `validation.mjs`: a `number-between` rule enforces an inclusive numeric bound (`message` defaults to `Please enter a number from ${min} to ${max}`) and a `dropdown` rule accepts only its trimmed `values` (`message` defaults to `Please select one of the following values: <values joined by ", ">`). A stored `message` is used verbatim, blank text always passes, and `parseAllowedValues` splits the dialog's comma-separated input.

Row filtering lives in `filtering.mjs`: `normalizeFilter` (null removes it; range, column keys and entries are validated), `columnMatches` (values list, `text-contains` case-insensitive, `greater-than` numeric, `before` parsed dates, `is-empty`/`is-not-empty`) and `filterHiddenRows(filter, values, cells)` — the data rows after the region's header line that fail at least one column entry (entries of different columns AND together). Filtering never rewrites `cells`: the server derives `hiddenRows` for the payload, so CSV export and pivot sources keep every hidden record and clear-filter restores the original order and values.

CSV lives on the server (`lib/csv.mjs`): `parseCsv`/`toCsv` (LF separators, no trailing newline, quoting comma/quote/CR/LF). `workbooks.mjs` adds `worksheetUsedRange`/`worksheetToRows`, `normalizeWorkbookName`/`nextWorksheetName`/`addWorksheet`/`renameWorksheet`/`csvFileName`.

Row/column structure is one pure module, `structure.mjs`: `applyRowOperation`/`applyColumnOperation` shift `worksheet.cells` and the ranges of `worksheet.validations` and `worksheet.filter` in place and return `{ok:true}` or `{ok:false,error}` untouched on rejection. The grid is fixed 20 columns (A–T) × 40 rows, so values pushed past the last line are dropped; raw formula text shifts with its cells and unpreservable references become `#REF!`; a rule or filter whose whole range is deleted is dropped, one losing a boundary line shrinks. `rewriteFormulaReferences(text, rewrite)` is the shared reference rewriter (quoted literals and foreign-sheet qualifiers excluded).

Range transfer is `transfer.mjs`: `normalizeTransferRange` (`"D1:B2"`, `"D1"` or `{start,end}` → normalized corners inside the grid), `offsetFormulaText(text, rowDelta, columnDelta, worksheetName)` (relative refs move, `$`-anchored parts and foreign sheets stay, off-grid → `#REF!`) and `transferUpdates(worksheet, request)` (pure).

Undo/redo is `history.mjs` `createWorkbookHistory()`: one stack pair per workbook id (limit 50), `capture(workbook)` snapshots the `cells`, `validations` and `filter` of every worksheet, `push` records a successful operation and clears the redo branch, `undo`/`redo` swap the snapshot in. The history is process memory only; the state each undo/redo writes goes through the normal store transaction, so it survives a refresh. `api.mjs` wraps the cell, transfer, row/column and filter writes with `updateRecorded` (snapshot before the change, push only after success).

## Seed state (identical for every scenario)
Workbook `Q3 Sales` (`wb-q3-sales`): worksheet `Sheet1` (`ws-q3-sheet1`) with the data region `A1:C6` — headers `Region`/`Sales`/`Status` in row 1, records `East/1200/Open`, `North/800/Closed`, `South/700/Open` in rows 2–4 (rows 5–6 empty), no rules, no filter, `activeCell`/`selectionFocus` `A1`; worksheet `Sheet2` (`ws-q3-sheet2`) blank. Sheet1 is active; `updatedAt=2026-09-15T08:30:00.000Z`. Mutually exclusive initial values stay separate and are reached through public operations (Import CSV, New blank workbook, cell entry, paste, Data menu), never by toggling seed values; the REQ-3 `Item/Qty` and REQ-4 `A1=2`,`B1=3`,`=A1+B1`,`=C1*2` states are prepared by hand in columns D–T / rows 5–40.

## UI conventions
- Home record: `<article>` with a link named after the workbook and the text `Last updated: <value>` (`formatLastUpdated` → `YYYY-MM-DD HH:MM UTC`). Editor: one `<main>` with `<h1>{workbook.name}</h1>`, `Rename workbook`, `Last updated: …`, the toolbar, the `Formula bar` text box, worksheet tabs and the grid.
- Rename (`RenameWorkbookForm`): inline form with a prefilled `Workbook name` box and `Save`/`Cancel`; a blank trimmed name is rejected beside the field with `Workbook name cannot be empty` (the server enforces the same). `Export CSV` downloads the active worksheet; the file name comes from `Content-Disposition`.- Worksheet tabs: `role="tablist"`/`tab`/`aria-selected`/`tabpanel`; clicking or arrow keys switch worksheets and persist `activeWorksheetId`. Each tab item holds a `Menu` trigger named `Worksheet options for <worksheet name>` opening a `role="menu"` of `role="menuitem"` commands (today `Rename`); the bar ends with `Add worksheet`. `RenameWorksheetDialog` is mounted only while renaming; empty/duplicate checks run beside the field and are enforced by the server.
- Grid: `role="grid"`, accessible name `Worksheet grid`, `aria-multiselectable="true"`, `role="row"`/`columnheader`/`rowheader`, 20×40 `role="gridcell"` named by coordinate (`aria-label="A1"`) with `aria-selected` from the selection rectangle. It renders `values[address] ?? cells[address]`; pressing a cell selects it, dragging extends the rectangle live (stored on mouse release; arrow keys and clicks store a single cell); a rejected selection restores the last accepted rectangle and shows the error.
- Editing: double-click, Enter/F2 or a printable key opens an inline box named `Edit <cell coordinate>` (`gridEditing.ts`), prefilled with the stored raw text; Enter commits and refocuses the cell, Escape discards, blur commits. The `Formula bar` box edits the anchor cell the same way. A commit sends one `POST .../cells`; grid and formula bar change only from the answer, so a rejected commit keeps the previous content and shows the error in the editor's `role="alert"`; a write marks the grid `aria-busy` and blocks a second one.
- Range transfer: the cell context menu (`Cell D1 menu`) lists `Cut`, `Copy`, `Paste` as `role="menuitem"`; Ctrl+C / Ctrl+X remember the selection rectangle, Ctrl+V (the `Paste` command or a paste event) places it (`rangeTransfer.ts`). A remembered rectangle belongs to one worksheet, so pasting in another falls back to the external clipboard text of REQ-3-1-2. Copy keeps the source, a cut clears it through the same atomic request, and the rectangle stays highlighted until a cut is used up.
- Structure menus: right-click or the context-menu key on a row number/column letter opens `GridContextMenu` (`Row 2 menu`/`Column B menu`), whose `role="menuitem"` commands follow `ROW_COMMANDS`/`COLUMN_COMMANDS` (`structure.ts`) — `Insert 1 row above`/`Insert 1 row below`/`Delete row`, `Insert 1 column left`/`Insert 1 column right`/`Delete column`. Header cells carry no trigger button, so their accessible name stays the plain number/letter; a rejected operation keeps the previous structure and shows the error.
- Toolbar: `Undo`, `Redo` (disabled while the session branch is exhausted), `Export CSV` and the `Data` menu. Ctrl+Z/Ctrl+Y do the same; after an undo, any new modification disables `Redo` and Ctrl+Y. Only the workbook payload decides availability.
- `Data` menu (`Menu` primitive, `role="menu"`/`role="menuitem"`): `Create filter`, `Clear filter`, `Data validation`. `Create filter` stores `{range, columns:{}}` for the selected rectangle when it covers more than one cell, otherwise for the data region of the `cells` bounding box (`filtering.ts` `filterRegionFor`), and reports `Select a data range with a header row to create a filter.` when there is none. `Clear filter` patches `filter: null`; `Data validation` opens the dialog for the current selection.
- Filtering (`FilterDialog.tsx`): every header column of the region renders an empty button named `Filter <header text>` on the right edge of its header gridcell (glyph via CSS, so the cell text stays the plain value). The dialog of the same name shows checkboxes for the column's distinct source values (name = value, blank cells excluded), `Clear selection`, a `Condition` combo box (`Text contains`, `Greater than`, `Before`, `Is empty`, `Is not empty`), a `Value` text box and one `Apply`: it stores a `values` entry when the checkbox selection changed, otherwise the chosen condition, and keeping every value clears that column's entry. Hiding is rendering only — a hidden row (`display:none` on its `role="row"`) keeps its cells, values and position.
- Data validation (`DataValidationDialog.tsx`): `Rule type` (`Dropdown` | `Number range`), `Allowed values` (dropdown) or `Minimum`/`Maximum` (number range), `Save` for the selected rectangle, prefilled from the first rule covering it and then also offering `Delete rule`. Saving sends the explicit prompt (`Please enter a number between <min> and <max>` / `Please select one of the following values: <values joined by ", ">`). A dropdown cell renders `Open dropdown for <cell coordinate>`; the popup is a `role="listbox"` of `role="option"` items named by the trimmed allowed value, and choosing one goes through the normal cell write. Rejected values keep the previous content and show the rule message in the editor's `role="alert"`.
