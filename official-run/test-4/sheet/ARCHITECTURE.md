# Architecture

## Entry points (hash routes)

- `#/` — workbook home: list of workbooks, "New blank workbook" (`#/new`), "Import CSV" dialog.
- `#/new` — creation page ("Workbook name" prefilled "Untitled workbook", submit "Create").
- `#/workbooks/:id` — editor: title + "Rename workbook", "Last updated:", tablist/tab, "Formula bar" textbox, ARIA grid "Worksheet grid". Direct entry; refresh restores the same workbook.

## Shared interfaces (same-origin JSON API)

- `GET /api/workbooks` → `{ workbooks: [{ id, name, updatedAt }] }` sorted by updatedAt desc.
- `POST /api/workbooks` `{ name }` → 201 full workbook (trim; empty → 400 "Workbook name cannot be empty").
- `GET /api/workbooks/:id` → full workbook (sheets carry derived `results`).
- `PATCH /api/workbooks/:id` `{ name }` → rename (same 400 rule), bumps updatedAt.
- `PATCH /api/workbooks/:id/cells` `{ sheetId, updates: { coord: value } }` → atomic: either every value applies or nothing changes (validation rejection throws before write); bumps updatedAt. Single-cell edits and two-dimensional pastes both go through this route.
- `POST /api/workbooks/:id/clipboard` `{ sheetId, kind: copy|cut, range }` → captures the rectangle's raw cell text (values and original formulas) into the workbook's session clipboard; never changes data.
- `POST /api/workbooks/:id/paste` `{ sheetId, target }` → pastes the clipboard so the rectangle starts at `target`: formula relative refs shift by the target offset (`translateFormulaRefs`), absolute `$A$1` refs stay; cut clears the source range. Atomic + validation-rejected before write; bumps updatedAt. Same-worksheet only (`Clipboard belongs to another worksheet`).
- `POST /api/workbooks/:id/undo` / `…/redo` → session history: restores the whole workbook snapshot (cells, formulas, structure, selection, rules) recorded before each cell edit, paste, and row/column op; a new modification clears the redo branch; bumps updatedAt. Errors `Nothing to undo`/`Nothing to redo`.
- Workbook responses carry session fields: `undoAvailable`, `redoAvailable`, and `clipboard` (`{ sheetId, kind, range } | null`).
- `PATCH /api/workbooks/:id/state` `{ sheetId, selectedCell, selectedRange?: { start, end } }` → sets active sheet + the sheet's selection (anchor + complete rectangle); no updatedAt bump.
- `PATCH /api/workbooks/:id/filter` `{ sheetId, filter }` → set/update (`{ start, end, columns: Record<letter, ColumnFilter> }`) or clear (`filter: null`) the sheet's filter view (REQ-5-1-2); rows are hidden only, never deleted/reordered; no updatedAt bump; per-sheet only.
- `PATCH /api/workbooks/:id/validation` `{ sheetId, ruleId?, start, end, type, allowed?|min?|max? }` → upsert a validation rule (ruleId edits the reopened rule, otherwise replaces an exact-range rule or creates one; trims dropdown items, drops empties; errors `Allowed values cannot be empty`, `Minimum must not exceed Maximum`); `DELETE …/validation` `{ sheetId, ruleId }` → remove (`Rule not found`). Both bump updatedAt and never change existing cell values (REQ-5-2-1).
- `PATCH /api/workbooks/:id/sort` `{ sheetId, start, end, column, order: ascending|descending, hasHeader }` → sorts only the selected rectangle by one of its columns (REQ-5-1-1); header row (hasHeader) stays put, rows move together, cells outside the rectangle are untouched; errors `Invalid sort range` / `Sort column outside range` / `Invalid sort order` leave the grid order unchanged; bumps updatedAt and records an undo snapshot.
- `POST /api/workbooks/:id/pivot` `{ sheetId, range }` → creates a pivot-result worksheet named by the first unused `PivotN` (Pivot1 first); the new sheet becomes active and starts with an empty config (REQ-5-3-1). `PATCH /api/workbooks/:id/pivot` `{ sheetId, config }` → applies `{ rowField, columnField?, valueField, summarizeBy: SUM|COUNT|AVERAGE }` and replaces the summary cells; `POST …/pivot/refresh` → recomputes with the stored config. Both are atomic: on error (`Pivot field is no longer available. Select a new field.` / `Value field requires numeric values` / invalid range) nothing is written — the last successful result and the source worksheet are preserved. All bump updatedAt and record an undo snapshot.
- `POST /api/workbooks/:id/sheets` → add worksheet (first unused `SheetN` name), becomes active; bumps updatedAt.
- `PATCH /api/workbooks/:id/sheets/:sheetId` `{ name }` → rename (trim; empty → 400 "Worksheet name cannot be empty", case-insensitive duplicate → 400 "Worksheet name already exists"); bumps updatedAt.
- `DELETE /api/workbooks/:id/sheets/:sheetId` → delete worksheet (REQ-2-1-4): last sheet → 400 "A workbook must contain at least one worksheet"; sheet still referenced as `pivot.sourceSheetId` by another sheet → 400 "Please delete or rebuild dependent pivot tables first" (both worksheets unchanged). On success the whole sheet (cells, formulas, validation rules, filter, pivot results) is removed; if it was active an adjacent sheet becomes active; bumps updatedAt; a session clipboard referencing the deleted sheet is cleared.
- `POST /api/workbooks/:id/rows` `{ sheetId, index, position: above|below }` / `DELETE …/rows` `{ sheetId, index }` → row insert/delete; `POST …/columns` `{ sheetId, index, position: left|right }` / `DELETE …/columns` → column ops; all shift cell coords and bump updatedAt.
- `POST /api/import-csv` `{ fileName, content }` → 201 workbook named file minus `.csv`; parse failure → 400 "Invalid CSV file format. Import failed." and no record.
- `/health` and `/api/health` → `{ ok: true }`; unknown paths/APIs → 404 JSON; PORT + platform-ports.json (3301) both served, `ARC_EXTRA_PORTS=0` skips extras.

## Persistence and seed

- Backend JSON store at `SHALLOW_DATA_DIR/workbooks.json` (default `<repo>/.data`), atomic writes via `createJsonStore`.
- Workbook model: `{ id, name, createdAt, updatedAt, activeSheetId, sheets: [{ id, name, cells: Record<coord, string>, selectedCell, selectedRange: { start, end }, validationRules, filter, pivot }] }`; coords like "A1", columns A…Z, AA…; `cells` stores the raw submitted text — ordinary values and original formulas ("=...") — never computed results. `selectedRange` is the complete persisted selection rectangle (anchor = `selectedCell`); `validationRules` holds REQ-5-2 rules (shape `{ id, start, end, type: "number", min, max }` or `{ id, start, end, type: "dropdown", allowed: string[] }`), enforced atomically in the cells and paste routes: a 0–100 rule rejects with "Please enter a number from 0 to 100", other numeric rules with "Please enter a number between <min> and <max>", dropdown rules with "Please select one of the following values: <comma-separated allowed>"; clearing a cell is always allowed. Row/column ops shift rule ranges with the constrained cells (a rule fully on a deleted row/column is dropped). `filter` holds the REQ-5-1-2 view: `{ start, end, columns: Record<column letter, { kind: "values", selected } | { kind: "condition", condition, value }> } | null`; the frontend computes visibility (`rowMatchesFilter`, header row and out-of-range rows always visible, conditions per column ANDed) and CSV export ignores the filter (hidden rows included). `pivot` is null on ordinary sheets; pivot-result sheets carry `{ sourceSheetId, sourceRange: { start, end }, rowField, columnField, valueField, summarizeBy }` plus the summary cells written by the last successful Apply/Refresh — results are NOT recomputed on read, they stay unchanged until "Refresh pivot table" (REQ-5-3-1). Pivot computation lives in `backend/src/lib/pivot.mjs` (`computePivotCells`: SUM/AVERAGE use only parseable numbers, COUNT counts non-empty value-field records and never fails on nonnumeric content; row/column groups in first-appearance order; A1 = row-field name, B1 = "<method> of <value field>", final row/column = Grand Total; empty combos display 0 for COUNT). Row/column ops shift the source ranges of pivots that read the affected sheet (`shiftPivotRanges` — results unchanged until refresh). Sorting (REQ-5-1-1) lives in `backend/src/lib/sort.mjs` (`sortRangeCells`): numbers, parseable dates, and text compare by type (numbers < dates < text, blanks last in both orders), equal keys keep original relative order (stable), formula text moves with its row so references stay relative and results recompute on the next read; filters and validation rules keep their coordinates unchanged.
- Formula engine: `backend/src/lib/formula.mjs` (`computeSheetResults`, `evaluateFormulaText`). Every API response attaches a derived `results: Record<coord, string>` per sheet (formula cells only); results are recomputed from stored text on every read, so the grid shows calculated results, the formula bar shows the original formula, and dependent formulas recalculate after source edits and refresh. Errors: #DIV/0!, #REF! (invalid/circular), #NAME?, #ERROR!. Aggregates ignore blanks/text; COUNT counts numeric only. `$`-locked absolute refs (`$A$1`, `$A1`, `A$1`) evaluate like plain refs; literal error tokens passed as aggregate arguments (e.g. `=SUM(#REF!)` after an out-of-bounds copy, REQ-4-1-2) propagate instead of counting as empty.
- Session-only per-workbook state (never persisted, may be empty after a server restart): undo/redo history stacks and the copy/cut clipboard in `workbooks.mjs` (`histories`, `clipboards` maps), keyed by workbook id so one workbook's undo never touches another.
- Shared seed (empty store only): workbook `Q3 Sales` with `Sheet1` (range `A1:C6`: headers `Region/Sales/Status`, rows `East/1200/Open`, `North/800/Closed`, `South/700/Open`; rows 5–6 empty) and blank `Sheet2`. This matches the REQ-5 family evaluation seed (REQ-5-1-2 / REQ-5-2-1 / REQ-5-3-1) and keeps the East/1200/North/800 records for the REQ-2 row/column structure scenarios. User changes persist. Note: the REQ-4 seed (`A1=2`, `B1=3`, `=A1+B1`, `=C1*2`) and the REQ-3-1 seed (`A1:B2` = `Item/Qty`, `Pen/4`) are mutually exclusive with this seed, so those scenarios remain executable through visible controls.
- Structure ops shift stored cell coordinates (rows/columns) and rewrite formula text via `backend/src/lib/refs.mjs` (`rewriteFormulaRefs`): A1 refs and ranges shift with the op; direct refs into a deleted row/column become `#REF!`. Results recompute after the shift. Pivot-range adjustment lands with its own feature package. `translateFormulaRefs` shifts relative refs by a paste offset (absolute refs unchanged) for REQ-3-2-1 copy/cut paste; REQ-4-1-2: a relative ref moved outside the worksheet (row < 1 / col < A) becomes a `#REF!` token in the target formula text, so the target formula bar shows the adjusted formula with `#REF!` and the grid displays `#REF!`.

## Frontend conventions

- `lib/workbooks.ts` typed API calls; `lib/spreadsheet.ts` coordinate helpers (`columnName`, `cellName`, `parseCoord`, `gridSize`, `formatDateTime`, `normalizeRange`, `rangeContains`, `parsePasteText`).
- Editor ARIA: worksheet tabs `role="tab"` + `aria-selected`; grid `role="grid"` `aria-label="Worksheet grid"` `aria-multiselectable="true"`; cells `role="gridcell"` with `aria-label` = coordinate and `aria-selected` per the full selection rectangle; grid renders ≥50×26 covering used range. Header row is inside the grid: column letters `role="columnheader"` (accessible name = letter), row numbers `role="rowheader"` (accessible name = decimal number), sticky top/left; `aria-rowcount` = data rows + header row. Hidden filter rows are skipped in rendering (row headers keep their original numbers).
- Toolbar "Data" button (`aria-haspopup="menu"`) opens a menuitem menu (REQ-5): "Create filter"/"Clear filter" (per sheet.filter), "Data validation", "Sort range", and "Create pivot table"; header cells of an active filter rectangle render "Filter <header text>" buttons, dropdown-rule cells render "Open dropdown for <cell coordinate>" buttons with an option-role listbox; `FilterDialog` (`Filter <header text>`: Condition combo — None + the five REQ-5-1-2 conditions — value checkbox list with per-value names, Clear selection, Apply), `ValidationDialog` (`Data validation`: Rule type combo Dropdown/Number range, Allowed values or Minimum/Maximum, Save, Delete rule), `SortDialog` (`Sort range`: Sort by combo named by the range's header texts — column letter fallback for empty headers — Order Ascending/Descending, Data has header row, Sort), `PivotCreateDialog` (`Create pivot table`: visible "Source range: <cell range>", "New worksheet" radio, Create), and `PivotEditor` (region "Pivot table editor": Rows/Columns/Values combos whose options are the current source header texts, Summarize by SUM/COUNT/AVERAGE, Apply, Refresh pivot table; opening with a deleted selected header shows "Pivot field is no longer available. Select a new field.") are in `components/`; matching logic lives in `lib/filter.ts`.
- Selection (REQ-3-1-3): click selects one cell; drag (mouse down + enter cells + up) selects the whole rectangle, persisted per worksheet via the state API. Reopening restores each sheet's own rectangle; switching sheets never overwrites another sheet's selection.
- Worksheet switching (REQ-2-1-2): clicking a tab (`switchSheet` in `EditorPage`) only sets `activeSheetId` locally and persists it (plus the target's selection) through the state API — no history entry, source worksheet untouched; grid, structure, selection, formula bar (raw `cells[coord]`, i.e. value or original formula), filter buttons and validation entry points all render from the target sheet. Reopen restores the last active tab and each sheet's own last confirmed selection; a sheet with no selection history selects A1.
- Tab bar: per-sheet `aria-label="Worksheet options for <name>"` button opens a `role="menu"` (menuitem commands: "Rename", "Delete"); "Add worksheet" button adds a sheet. "Delete" with one sheet shows "A workbook must contain at least one worksheet" without a dialog; otherwise a `DeleteSheetDialog` (dialog "Delete worksheet", visible text names the target, "Delete worksheet" confirm button) confirms, and a rejected confirm (pivot source) closes the dialog and shows the server error while the tab stays. Right-clicking a row/column header opens the same menu component with "Insert 1 row above/below", "Delete row" (columns: left/right, "Delete column"); right-clicking a grid cell opens a menu with "Paste". `components/Menu.tsx` implements menuitem keyboard nav (arrows, Home/End, Enter, Escape); focus returns to the trigger on close.
- Editing (REQ-3-1-1): click cell selects; formula bar and inline cell input commit via the cells API (Enter or clicking another cell commits, Escape cancels). Double-clicking a cell opens an inline text box with accessible name "Edit <cell coordinate>"; grid displays `results[coord] ?? cells[coord]`, formula bar displays raw `cells[coord]`.
- Paste (REQ-3-1-2): Ctrl+V (grid `onPaste`) and the "Paste" menuitem parse external clipboard text into a tab/newline rectangle (`parsePasteText`), preserving empty fields, and submit the whole rectangle atomically through the cells API; a rejected paste keeps every target cell unchanged and shows the error.
- Range transfer (REQ-3-2-1): cell context menu provides "Copy", "Cut", "Paste" menuitems; Ctrl+C / Ctrl+X / Ctrl+V plus undo/redo keys (Ctrl+Z / Ctrl+Y) are handled by a window-level keydown listener in `EditorPage` (skips inputs, dialogs, menus), so the shortcuts work without grid focus. Ctrl+V prefers the session range clipboard and falls back to external text. Toolbar buttons "Undo"/"Redo" are disabled per `undoAvailable`/`redoAvailable`; clicking a cell on mousedown focuses it so shortcuts land on the grid.
- Dialog wrapper (`components/Dialog.tsx`) provides `role="dialog"` with accessible name, Esc/overlay close, focus trap, initial focus.
- CSV parsing is server-side (`backend/src/lib/csv.mjs`): quoted commas, `""` escapes, embedded newlines, CRLF, empty fields; unclosed quote → error. CSV export writes formula results for formula cells.
