# Architecture Notes — GitHub Collaboration Platform

## Stack
- `frontend/`: React 18 + Vite + TypeScript, hash routing (no router lib), Vitest + Testing Library.
- `backend/`: zero-dependency Node `http` (ESM), node:test. Persistent state via `backend/src/lib/json-store.mjs` (atomic JSON writes, serialized queue).

## Platform contract
- Backend reads `PORT` (default 3000) and also listens on `backend/src/platform-ports.json` ports (3301) on all interfaces; skipped only when `ARC_EXTRA_PORTS=0`. One `http.createServer` per port.
- `GET /health` and `/api/health` return the same response. `/` serves `frontend/dist`; unknown paths return 404 without exiting.
- Persistent state: `${SHALLOW_DATA_DIR}/state.json` (fallback `backend/data/state.json`); never return a mutator result from `store.update` — capture results in closures.

## Backend interfaces
- `backend/src/domain/accounts.mjs` — account/session/recovery domain:
  - Validation: username `^[a-z0-9](?:-?[a-z0-9]){0,38}$`; email one `@`, ≤254, dotted labels; password 12–128 with four char classes, no whitespace.
  - Passwords stored as salted SHA-256; never echoed. `seedState` seeds `alice-dev` / `alice.dev@example.test` / `Valid-password-123!` only into an empty store. Recovery code fixed `123456`.
- `backend/src/domain/organizations.mjs` — org/team/repo domain: collections `organizations`, `organizationMembers` (`{organizationId, accountId, role}`), `repositories` (`ownerId/ownerType`, name, description, `visibility`, defaultBranch, sourceRepositoryId, `branches: [{name, commitId, protected}]`, `commits: [{id, parentId, authorAccountId, authorName, message, createdAt, changes, files}]`), `teams`, `teamMembers`, `repoGrants` (`subjectType`, role).
  - Org name = REQ-1 username regex; display name 1–100 after trim; team name `^[a-z0-9]+(?:-[a-z0-9]+)*$` ≤50, unique per org; parent same org and acyclic. `effectiveRepositoryRole` = highest of Owner admin, account grant, team grants (no hierarchy propagation). `seedOrganizations` (empty only): org `acme-demo` (display `Acme Demo`), owner `alice-dev`, member `bob-reviewer`, repos `acme-docs` (public) + `acme-internal` (private), teams `platform-team` → `frontend-team` → `frontend-child` + `docs-team`.
- `backend/src/domain/repos.mjs` — personal repos, files, search, forks, creation, visibility:
  - `seedRepositories` (no account-owned repo yet): alice-dev `acme-docs` (public), `secret-research` (private, bob read grant), `acme-docs-fork` (private conflict seed).
  - Repo name `^[a-z0-9](?:[a-z0-9._-]*[a-z0-9])?$` ≤100. `createFork` (Read source + create perm; conflict → `Repository name already exists`), `changeRepositoryVisibility` admin only, `createRepository`, `changeDefaultBranch` (admin; branch must exist; never rewrites), `describeRepository`.
- `backend/src/domain/vcs.mjs` — version control (REQ-4/6): `canWriteRepository` (write/maintain/admin), `branchSnapshot`, `branchCommitList` (+`path`), `createFileCommit` (path rules; message 1–72; protected → `Branch is protected`), `commitDiff`, `compareDiff` (+`path`), `compareBranches` → `{commitCount, commits, files, noDifference}` (also used by pulls), `isValidBranchName` (1–255, no `..`/`//`), `createBranch`, `searchCode`, `fileLanguage`, `normalizeRepositories`, `makeSeedCommit` (changes by LCS). LCS `diffSnapshots` → `{path, status, additions, deletions, lines}`; zero-`+/-` omitted.
- `backend/src/domain/issues.mjs` — issue domain (REQ-5): collections `labels`, `milestones`, `issues` (per-repo number, title/description/state/author/assignees/labels/milestone/timestamps), `issueComments`, `issueReactions`, `issueActivities`. Roles: write+ edit/comment/create; triage+ metadata + close/reopen; title 1–256 after trim (`Title is required`), ≤65536. `seedIssues` into both acme-docs repos: labels `bug`/`documentation`, milestones `Q3 launch` + `v1.0`, open #1 `Improve onboarding`, closed #2 `Legacy welcome text`, open #3 `Original issue title`; bob grant: personal acme-docs `write` (REQ-6-3/6-4 reviewer seed), org acme-docs `triage`; `acme-internal` has `bug`/`priority-high` + `Backlog`.
- `backend/src/domain/pulls.mjs` — pull-request core (REQ-6): collections `pullRequests` (per-repo `number`, title/description/author/status open|draft|closed|merged, `baseBranch`/`compareBranch`, creation-time `baseCommitId`, current `compareCommitId` synced from compare-branch head, `activities`, `reviews [{accountId, decision, commitId, explanation, createdAt}]`, `inlineComments [{accountId, path, line, commitId, body, published, reviewId}]`, `reviewerRequests [{accountId, requestedByAccountId, createdAt}]`, `checks [{name, commitId, status, setterAccountId, setAt}]`) and `branchProtectionRules` (`{repositoryId, branch, requireApproval, requireStatusCheck}`).
  - `canCreatePullRequest` = write/maintain/admin; `createPullRequest` atomically rejects same branches, no comparable commits, existing Draft/Open pair, empty/overlong title, missing permission; `draft: true` → Draft. `markPullRequestReadyForReview` (author or maintain/admin) Draft → Open. `canClosePullRequest` = author or maintain/admin (incl. org Owner); `closePullRequest` (open|draft → closed; never merges or touches branches; stores `closedAt` + closed activity), `reopenPullRequest` (closed → open; clears `closedAt` + reopened activity); Merged is terminal and rejected server-side. Checks Admin-only per current compare commit. `mergeEligibility`: latest review per reviewer on current commit only; author cannot approve; Request changes blocks; rule toggles add `Review required by branch protection` + `Requires status check test to be success`; merge-conflict detection. `upsertProtectionRule` (Admin-only) marks branch protected. `pullRequestDetail` includes comments/inlineComments/reviewers/reviewSummary/reviewerCandidates/merge + `canReview`/`canMerge`/`canRequestReviewers`; `pullRequestSummary` has `reviewed`. `mergePullRequest` (maintain/admin; rereads eligibility; merge commit with `parentId` = base head + `secondParentId` = compare commit; updates base head; Merged + `mergedByAccountId`/`mergedAt`/`mergeCommitId`; merged activity). `seedPullRequests` (personal acme-docs only, see Seed section).
- `backend/src/domain/pull-review.mjs` — review/comment/reviewer/merge helpers (REQ-6-3/6-4/6-5): `canReviewPullRequest` (non-author write+ on Open), `addInlineComment` (path/line must be a changed diff line; `startReview` → unpublished; body trimmed ≤65536; `Comment is required`), `submitReview` (decision in comment|approve|request_changes; publishes that reviewer's pending comments; old records preserved), `canMergePullRequest` (maintain/admin), `mergeConflict`, `canRequestReviewers` (author of Open/Draft, or maintain/admin/org-owner by role regardless of PR status), `eligibleReviewers` (write+ non-author), `requestReviewer`/`removeReviewerRequest` (removal keeps reviews/comments).
- API routes (`backend/src/server.mjs`): POST `/api/accounts/register` (400 + `errors`), POST `/api/sessions` (401 `"Invalid credentials"`; HttpOnly cookie `shallow_session`), GET/DELETE `/api/sessions/current`, POST `/api/accounts/password`, POST `/api/recovery/request|reset`.
  - Organization routes: GET/POST `/api/orgs`, GET `/api/orgs/:name` (+`/repos|members|teams`), POST `/api/orgs/:name/members|teams`, DELETE `.../members/:username` (owner), GET/PATCH `.../teams/:team`, POST/DELETE `.../teams/:team/members[/:username]` (owner).
  - Grant routes (owner/repo-admin): GET/POST `/api/orgs/:name/repos/:repo/grants`, PATCH `.../grants/:subjectType/:subject`. Roles read/triage/write/maintain/admin.
  - Repository routes: GET `/api/search/repositories?q=`, GET `/api/users/:username/repos`, GET/PATCH `/api/users/:username/repos/:repo` + org equivalents (PATCH = visibility, admin only), POST `/api/forks|repositories`. Repo GET accepts `?branch=` (unknown → 404).
  - Code routes (REQ-4, `backend/src/routes/code-routes.mjs`): GET `.../commits?branch=&path=`, GET `.../commits/:id`, GET `.../compare?base=&compare=&path=`, GET `.../search?q=&branch=&path=&language=`, POST `.../branches`, POST `.../files`, PATCH `.../default-branch`. Commit ids `commit_<uuid>` (short = first 7 chars).
  - Issue routes (REQ-5, `backend/src/routes/issue-routes.mjs`): GET/POST `.../repos/:repo/issues`, GET `.../issues/:number`, PATCH (title/description; write+), POST `.../state` (triage+), POST `.../comments|assignees|labels|milestone|reactions`.
  - Pull routes (REQ-6, `backend/src/routes/pull-routes.mjs`): GET/POST `.../pulls`, GET `.../pulls/compare?base=&compare=` (write+), GET `.../pulls/:number`, POST `.../pulls/:number/ready|checks|reviews|comments|reviewers|close|reopen|merge`, DELETE `.../pulls/:number/reviewers/:username`, GET/POST `.../protection-rules` (POST Admin only). List/detail sync the current compare commit to the branch head.

- `frontend/src/pages/orgs/` — `OrganizationsPage`, `NewOrganizationPage`, `OrganizationPage` (Repositories/People/Teams tabs), `PeopleTab` (`Add member`, `Remove from organization`), `NewTeamPage`, `TeamPage` (`Add member`, `Remove <username>`, `Parent team` + `Save`), `ManageAccessPage` (`Add people or teams`, `Role` select, `Add`/`Save`).
- `frontend/src/pages/search/` — `SearchPage`, `CodeSearchPage` (`Code` results link, `Path`/`Language` filters, `No code results`).
- `frontend/src/lib/` — `api.ts` (`apiRequest`/`ApiError`), `pull-api.ts` (types + `fetchPullRequests`/`fetchPullRequestDetail`/`fetchBranchComparison`/`createPullRequest`/`markPullRequestReadyForReview`/`updatePullRequestCheck`/`addInlineComment`/`submitPullReview`/`requestReviewer`/`removeReviewer`/`mergePullRequest`/`closePullRequest`/`reopenPullRequest`/`fetchProtectionRules`/`saveProtectionRule`; `PullDetail.canClose`), `issue-api.ts`, `org-api.ts`, `repo-api.ts` (`RepoOwnerType`, href helpers).
- `frontend/src/pages/forms/` — `SignInForm` (`Username or email`, `Password`, `Sign in`, links `Create an account`/`Forgot password`), `SignUpForm`, `RecoveryForm` (code `123456`). `SettingsPage.tsx` — password + `Update password`.
- Field errors are exact messages beside the field; passwords never redisplayed.
