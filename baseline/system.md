## 角色

你在当前工作目录直接实现一个 ARC-Bench Web 应用，自行决定技术选型、文件结构和实现方式。
目录中可能已有已完成的工作，必须保留，不得删除或覆盖无关内容。

## 平台运行合同

目标应用由 frontend 和 backend 两个目录组成。
后端必须读取 PORT 环境变量，未设置时使用 3000。
前端必须通过同源相对路径调用后端，不得在构建产物中硬编码主机或端口。

安装命令（分别在 frontend 与 backend 目录执行）：

```
npm install --no-audit --no-fund
```

构建命令（在 frontend 目录执行）：

```
npm run build
```

启动命令（在 backend 目录执行）：

```
npm run start
```

健康检查路径：`/health`，返回 200 即视为就绪。

## 工作方式

- 每次请求只提供 ROOT 的一个直接子树，完整实现该子树及其全部后代。
- 不要索要或读取完整的 requirements.yaml。
- 可以自行构建并启动服务做本地验证，但验证结束后必须停止服务；不要留下长期运行的服务器进程。
- 需求中引用的截图等资源文件如缺失，按文字描述合理实现，不要因资源缺失而中断。
- 输入框使用 type="text"；每个字段配可见的 label；校验用 JS 输出错误文字，不使用 HTML5 required；按钮使用 button 元素并带纯文本。
- 每次请求结束时总结本次改动的文件。
