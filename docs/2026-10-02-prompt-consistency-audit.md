# 提示词一致性检查与精简

检查范围：`prompts/` 的 31 份资产、`baseline/system.md`，以及 Builder、Judge、功能分组、baseline 和共享 Worker 的实际装配、工具与校验合同。度量以本轮开始时的工作区为基准，包含此前已完成的新需求适配。

## 已修正的偏差

| 位置 | 问题与最终行为 |
| --- | --- |
| Judge Planner | 原来要求创建和编辑使用不同于种子的名称，会覆盖重复名称场景的指定输入。现在成功创建按场景使用未用值，重复、冲突和指定名称保持原值；编辑只修改指定字段。 |
| Judge 连续操作 | 原来“每份计划最多一条连续链”与完整还原多个连续场景冲突。现在场景本身的完整链优先，仅额外构造的跨功能回归链限制为一条。 |
| Judge 复核 | `coverageReview` 在开头与运行失败复核分流。未执行计划只判断设计完整性；运行复核才要求已执行的初始状态证据。结果分项映射不能代替实际断言。 |
| Judge wire 示例 | 例子补齐 locator 的 nullable 字段；refinement 保留 firstMatch 引用，第一条 changed line 选择仍须明确的具名控件与容器关系。 |
| Builder 修复 | 管线两轮边界修复都使用 repair 模式，任务标签改为“需求修复”。准备、定位诊断和重复控件保护进入共享自测合同，根因修复同样收到。 |
| 领域片段 | 领域对象清单限定为本包涉及的对象；持久化和更新时机以需求为准，避免把过滤或切换等界面暂态一律要求永久保存。 |
| generic_web 片段选择 | 补读需求正文及已经传入的产品/祖先合同；普通 ARIA role、region 不再触发权限或电子表格片段。结构化失败信号和已识别产品的基础片段保持原行为。 |
| baseline | 实际探针、评测和额外端口进入模块提示词；说明 run_tests 的 Vitest/node:test 合同及场景初态。保留自主选栈、单会话和 ROOT 子树输入。 |
| 功能分组 | 明确 externalDependencyIds 仅为前序上下文，不加入本轮 groups 或依赖排程。 |
