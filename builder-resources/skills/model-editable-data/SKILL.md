# 建模复杂可编辑数据

## 工作流

1. 从当前需求识别记录、字段、稳定身份、显示顺序、选择范围、原始输入、派生结果及临时编辑草稿；不得预设具体产品领域。
2. 先用类型和纯函数表达单项编辑、批量变换、结构变化、依赖失效及历史操作，再连接组件和持久化。
3. 为一次用户动作构造候选下一状态：完整解析并校验全部输入，计算相关派生结果，然后原子提交；任一步失败都保留最近成功状态。
4. 让直接编辑、详情编辑、批量输入、导入、撤销重做等写入路径复用同一套解析、校验和引用调整规则。
5. 用纯函数测试覆盖边界索引、空值、非法输入、依赖传播、范围变化和历史恢复；用组件测试覆盖键盘、焦点、ARIA 状态与可见结果。
6. 只有传统 DOM 测试无法确认真实剪贴板、焦点或原生弹层行为时才启动 browser。

## 数据不变量

- 记录以稳定 ID 访问；筛选、排序或移动只改变视图或顺序，不改变身份。
- 二维或分区布局需要语义位置时，明确坐标与稳定身份之间的映射；显示索引变化不能悄悄改变引用对象。
- 原始输入与显示结果分开保存或推导，编辑器展示哪一种由交互上下文明确决定。
- 选择使用锚点和活动端表达，并在插入、删除、过滤或切换上下文后规范化到有效范围。
- 批量写入、移动、排序、导入和删除必须全部成功或全部失败，不留下半应用状态。
- 结构变化同步处理引用、验证范围、选择、缓存和派生结果的失效状态。
- 引用表达式区分相对与固定部分；复制、移动和结构变化通过同一个纯变换入口调整引用。
- 派生计算应检测循环或无效依赖，错误以可观察且稳定的状态传播，不能静默使用陈旧结果。
- 撤销重做记录领域事务及其逆操作，不记录悬停、弹层开关等临时 UI 状态。
- 独立编辑上下文分别保存选择与草稿；切换时不得把未提交临时状态泄漏到另一个上下文。

## 交互与性能

- 键盘事件先判定编辑模式、导航模式和弹层模式，避免同一按键触发两条路径。
- 提交编辑时维持明确焦点目标；取消编辑恢复原值，成功编辑呈现权威结果。
- 大集合使用按 ID 的规范化状态、记忆化派生和局部渲染；只有实测需要时才引入窗口化。
- 依赖图只重算受影响节点，并保持确定顺序；先保证正确性，再根据真实热点优化。
- 持久化序列化领域状态，不保存 DOM 引用、瞬时焦点或不可重放的回调。

不要按需求 ID、示例数据或测试文案返回硬编码结果。这个技能只定义可迁移的工程不变量；具体结构、字段语义、计算规则和初始数据必须由当前需求与项目推导，并由本次模型调用实现。
