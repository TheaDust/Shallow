## Builder 浏览器自测

本次 OpenCode 会话提供 `playwright` 浏览器工具。把自测作为本次实现或修复的一部分，在完成回执前执行。

1. 完成代码修改后，调用 `candidate` MCP 的 `prepare` 工具。控制器在私有应用副本中按平台合同安装依赖、构建并启动自测实例，返回 `baseUrl`。用该地址自测；正式评测端口 3000 保持空闲。无需自行重复安装、构建或启动服务；准备失败时依据工具错误修复应用，再调用 `prepare`。
2. 使用 Playwright 工具实际打开页面，通过 `browser_snapshot` 获取当前页面结构，再按工具参数操作对应元素，完成当前工作包的一条关键用户路径并检查可见结果；需求涉及持久化时再刷新验证。修复模式优先复现并重新验证本次失败现象；交付修复只检查健康状态、根页面及交付故障相关路径。
3. 检查相关控制台错误和失败请求。发现产品问题时，先调用 `candidate` MCP 的 `stop`，再修改输出目录中的代码，随后重新调用 `prepare` 并验证受影响路径。代码修改会使之前的构建凭据失效；只做与本次任务有关的检查，控制自测规模。
4. 使用独立的临时业务对象，检查后清理自己创建的数据；保留需求预置数据和已有用户数据。浏览器配置隔离不代表服务端数据隔离。
5. 结束前调用浏览器关闭工具，再调用 `candidate` MCP 的 `stop`，由控制器停止自测应用及其子进程，释放自测端口。控制器会在会话结束时再次清理；如曾自行启动额外进程，只处理自己记录的进程，不终止无关进程。
6. 在回执中写明实际操作、观察到的结果和未完成检查的原因。工具无法使用、构建失败或页面打不开时如实标记“未执行”或“失败”，不能写成通过。

自测依据仅为当前需求和允许的外部观测。测试文件、截图和输出属于开发诊断；自测不读取隐藏探针、控制器台账或官方测试，不替代独立 Judge 验收，也不改变本次调用的超时和尝试上限。

应用需要写入数据库、上传文件或运行日志时，使用 `SHALLOW_DATA_DIR` 环境变量指定的目录；未设置时使用应用自己的缺省数据目录。种子数据作为应用输入保留，由应用初始化到数据目录。源码和构建产物在应用运行期间保持不变。自测与 Judge 复用构建产物，但分别启动应用实例；自测数据仍须按第 4 步清理。
