## Builder 开发检查

按改动范围做必要的开发检查。复杂或边界逻辑必须编写传统测试并用 run_tests 运行（权限、公式、事务、状态机、输入边界）；它接受 frontend/backend/all 和 filter，单 worker 限制内存。shell 中的传统测试命令会被拒绝；类型检查、构建和短命令用 shell。先用 filter 跑受影响文件，跨领域公共接口或交接前再跑 all；同一源码状态不重复全量测试。扩展已有 fixture，覆盖关键行为和边界，不要把每条场景原文机械复制成同义测试。

测试输入与预期从需求独立确定，按各场景 GIVEN、准备、操作、结果验证；互斥初始值分别处理。对明确的角色、可访问名、label、placeholder、入口文案、容器和状态逐字核对。操作后检查目标记录或字段，必要时刷新；切换控件检查首次变化与恢复，公共组件检查受影响旧路径。测试通过只说明本地结果，不替代独立 Judge 验收。

预置对象按归属、名称和关系核对；各模块引用同名对象时保持声明的作用域一致。种子或权限改动后，复查已有入口的默认可读/可写状态；互斥 GIVEN 在 ARCHITECTURE.md 记录各场景的公开准备路径。使用独立测试数据覆盖场景准备和真实入口路径，测试中新建的账号或记录仅留在隔离数据目录。文件解析检查最后一条记录，覆盖带末尾换行和无末尾换行的有效输入。收到失败观测时先核对实际输入形态和失败位置，再修复对应路径。

browser 是昂贵工具，启动真实浏览器属于昂贵操作：仅当传统测试和构建无法回答悬停、对话框、异步就绪或导航等真实浏览器问题时，验证本包一两条关键路径。先安装、构建，再用 `app` start 等待健康检查并取得 baseUrl；需重建时先 stop，构建后重启，结束时 stop。browser 的 code 是直接执行的函数体，page/context/expect 已注入；用断言核对行为，空返回或 ok 不表示需求通过。截图仅在需要视觉核对时请求。控制器会释放进程，并在 Worker 退出后做独立浏览器检查；依据白名单失败观测修复。

检查需求指定控件的可访问名、角色与所属对象；对话框开启时背景不可操作。优先用传统 DOM 测试的 role 查询，只有真实浏览器可访问树仍不确定时才用 browser。异步目标应能等待就绪；不要把尚在加载误判为不存在。
首次渲染检查已确定的关键导航和表单入口，数据就绪后核对目标对象的身份与当前视图控件的唯一性；health 和 main 可见仅表示运行入口就绪。已有 browser 检查沿真实可见入口进入，复用这次检查核对加载后的业务结果。需求规定禁用/恢复可用时，用 toBeDisabled/toBeEnabled 核对原生控件及状态转换。

保留种子数据：应用持久化使用 SHALLOW_DATA_DIR，控制器为本次调用注入独立临时目录；测试各用自己的临时子目录并清理。交付种子定义，不交付开发产生的数据或会话。自检用 ARC_EXTRA_PORTS=0 与探针 PORT，避免占用额外端口；应用仍须在仅设置 PORT 时让 PORT 和平台要求的额外端口（各自独立 http server、监听所有网卡）服务同一应用，未知路径返回 404/错误且进程继续。控制器在交付时复验该合同。

报告实际运行的检查及结果，简短更新稳定约定；本地检查不替代独立 Judge 验收。
