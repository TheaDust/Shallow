## Builder 开发检查

按改动范围做必要的开发检查。复杂或边界逻辑必须编写传统测试并用 run_tests 运行（权限、公式、事务、状态机、输入边界）；它接受 frontend/backend/all 和 filter，单 worker 限制内存，默认实际执行。只对独立于运行数据和构建产物的确定性测试设置 reuse=true：同一 Worker 内 target/filter 相同且整个项目源码、测试、配置与锁文件摘要未变时复用成功结果；状态与集成检查按当前输入实际执行。shell 中的传统测试命令会被拒绝；类型检查、构建和短命令用 shell。先完成同一改动面的实现与测试，再用 filter 跑受影响文件；失败按输出修正相关原因后复跑，跨领域公共接口或交接前再跑 all。同一源码状态不重复全量测试、类型检查或构建；依赖声明与锁文件未变且安装已成功时沿用现有依赖。扩展已有 fixture，覆盖关键行为和边界，不要把每条场景原文机械复制成同义测试。

测试输入与预期从需求独立确定，逐场景核对 GIVEN、准备、WHEN 操作和全部 THEN 结果；互斥初始值分别处理。按系统合同的等价条件复用检查，保留独立的输入、权限、反向操作和结果约束；结合测试、代码核对与必要的真实交互确认覆盖，未检查部分在回执说明。逐字核对角色、可访问名、label、placeholder、入口、容器和状态。操作后检查目标记录或字段；要求刷新、重开或失败后原状态不变时逐项验证，切换检查首次变化与恢复，公共组件检查受影响旧路径。

预置对象按归属、名称和关系核对，跨模块保持声明的作用域；分别检查 URL 标识符、显示名和需求规定的完整组合标题，沿规定入口进入对象，刷新后复查身份。种子或权限改动后，复查既有入口的可读/可写状态。用隔离数据检查公开准备和真实入口，测试新建账号或记录不进入交付。文件解析检查最后一条记录，覆盖带末尾换行和无末尾换行的有效输入。

入口检查使用场景规定的身份和起点；登录后分别核对个人拥有、组织关系和直接授权所允许的对象，不能用另一身份或未声明的地址绕过入口缺口。下载功能检查实际下载的文件名和内容；表格导出按需求区分公式文本与计算结果，并复查导出前后的工作表状态。

涉及账户、组织或仓库入口时，在正式构建的应用中从首页登录，逐段检查工作台对象入口、账户菜单到安全设置与登出确认、组织列表到对象详情。每段点击后核对目标页面或对话框及下一段具名控件；分别检查首次进入、刷新和切换身份后的入口及权限。依赖异步数据的入口检查先确认列表就绪，再继续操作；菜单和页面导航控件须与所属页面一起稳定呈现。

收到失败观测时先核对输入形态和失败位置。类别 precondition 表示准备未完成；locator 表示定位尚需诊断，不能据此认定目标业务失败。按需求与页面观测核对归属、状态、记录、权限和公开准备路径，区分数据缺失与控件缺失。重复控件不得为消除定位歧义而随意重命名、隐藏或删除；保留已通过路径，证实与需求冲突时按原文修正并复查。

失败定位器的角色不自动成为实现要求；页面已有同名可操作控件时，先核对角色的原文依据。修改公共菜单、设置或其他入口前，检查其既有角色、名称和所属容器合同，并保留受影响旧路径的测试预期。

browser 是昂贵工具，启动真实浏览器属于昂贵操作：仅当传统测试和构建无法回答悬停、对话框、异步就绪或导航问题时，验证本包一两条关键路径。先安装、构建，再用 `app` start 等待健康检查并取得 baseUrl；重建前 stop，构建后重启，结束时 stop。browser 的 code 是直接执行的函数体，page/context/expect 已注入；用断言核对行为，空返回或 ok 不表示需求通过。截图仅在需要视觉核对时请求。控制器会释放进程，在 Worker 退出后做独立浏览器检查；依据白名单失败观测修复。

优先用传统 DOM 测试的 role 查询，核对首次渲染入口、数据就绪后的目标身份和同名控件的容器。对话框开启时背景不可操作；禁用和恢复用 toBeDisabled/toBeEnabled 核对原生或 ARIA 状态及实际效果。异步目标应能等待就绪；health 和 main 可见只表示运行入口就绪。

保留种子数据：持久化使用 SHALLOW_DATA_DIR，控制器为本次调用注入独立临时目录；测试各用临时子目录并清理。交付种子定义，不交付开发数据或会话。自检用 ARC_EXTRA_PORTS=0 与探针 PORT，交付按本次平台合同复验仅设置 PORT 的启动行为。

报告实际运行的检查及结果，简短更新稳定约定；本地检查不替代独立 Judge 验收。
