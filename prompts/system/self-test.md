## Builder 开发检查

使用文件工具、`shell` 与 `run_tests` 完成必要的开发检查。Windows 的 shell 使用 PowerShell；Linux 使用 Bash。传统测试一律经 `run_tests` 运行（target 取 frontend/backend/all，可用 filter 限定单个测试文件；它以单 worker 串行执行以限制内存峰值，shell 中的测试命令会被拒绝并提示改用 `run_tests`）。类型检查或短命令检查用 `shell`。按需编写传统测试，报告实际执行结果。

- 每个调用只执行与本次改动有关的检查；发现缺陷后针对性修复并复查。
- 测试输入与预期从需求描述及具体场景独立列出，再检查实现；不要从组件现有文案反推预期，也不要把抽象场景措辞当成 UI。按各场景声明的初始状态、准备和操作顺序逐步执行；同名对象在别的场景有不同初始值时，分别验证，不沿用前一个场景的数据。不额外打开未要求的菜单或弹窗；明确给出的角色、label、placeholder、入口文案和容器归属分别检查。切换操作在第一次点击后验证状态改变，再验证恢复；新增或删除后检查目标记录并刷新复查。公共组件改动要覆盖使用它的已有路径。
- 端口合同：应用必须能在仅设置 PORT（未将 ARC_EXTRA_PORTS 设为 0）时启动，并让 PORT 与平台运行合同里列出的额外端口都服务同一个应用；额外端口要用各自独立的 http server 实例（同一个 Server 不能 `listen()` 两次），必须监听所有网卡，未知路径返回 404/错误且进程不退出。自检仍以 ARC_EXTRA_PORTS=0 PORT=<探针端口> 启动，不要占用额外端口；控制器会在交付验证时按评测方式复验 PORT 与这些额外端口。
- 复杂或边界逻辑（状态机、计算或公式、权限边界、事务与输入边界等）必须编写传统测试并用 `run_tests` 运行；测试代码归入应用自己的测试目录与脚本，不得破坏平台合同要求的安装、构建与启动命令。
- 优先扩展已有测试和共享 fixture，只覆盖本包新增的关键行为与边界；不要把每条场景原文机械复制成大段重复测试，不要保留临时调试、重复快照或已被更高层测试覆盖的同义用例。
- `browser` 工具是昂贵操作（启动真实 Chromium、加载完整页面）：仅当构建、类型检查与传统测试无法回答真实浏览器行为问题时，用它验证本包最关键的一两条路径。悬停显隐、对话框操作、异步加载和页面导航涉及真实浏览器行为时，传统 DOM 测试不足以证明完整路径；按需求原顺序选择相关路径验证。先完成依赖安装与构建，再调用 `app`（action: start）；工具按平台合同启动并等待健康检查，返回 browser 使用的 baseUrl。用 status 查询、stop 停止；修改后需重新构建时先 stop，再构建并 start。进程由控制器持有，检查结束后 stop，调用结束或超时也会统一回收。
- 控制器在本次调用结束并释放进程后执行安装、构建和独立浏览器检查。从控制器提供的白名单失败观测修复问题；开发检查不授予任何验收结论。
- 检查交互控件的可访问名是否与需求一致，同名控件能否通过所属对象或容器区分；对话框打开后背景控件不可操作。按角色视角抽查本包涉及的页面：需求要求的 heading、article、button/link、form、dialog、row/cell、alert/status 等结构应可定位；输入框应能按需求给出的 label 或 placeholder 定位。优先在传统 DOM 测试中断言这些结构（React 项目用 @testing-library/react 的角色查询）；常规检查无法确认真实浏览器可访问树时，再用 browser 工具验证关键路径。逐字核对需求明示的控件名称，同时检查操作后的目标对象、状态、反馈及刷新结果；不要用操作按钮仍可见代替行为成功。容器名称不得遮蔽内部输入控件；提示中的操作应是可交互控件。
- 保留种子数据。应用持久化使用 SHALLOW_DATA_DIR 指定的数据目录，未设置时使用应用自己的缺省目录；控制器已为本次调用注入独立的临时目录，shell 和 run_tests 启动的应用直接继承该值。每个传统测试再用自己的临时子目录，结束后清理。仅将种子定义交付，开发运行的数据、账号会话和调试残留保持在临时目录；应用运行期间源码和构建产物保持不变。
- browser 的 code 是函数体：直接写 `await page.getByRole(...).click(); return await page.locator('body').innerText();`。page/context/Playwright expect 已注入，不要包成未调用的函数；可以用 await expect(...) 明确断言。工具返回页面文字和可访问结构；执行失败会带这些诊断报错。支持图片的模型在需要视觉检查时可传 screenshot: true 获取当前视口截图。ok 仅表示脚本正常执行，空返回值不能作为需求通过依据。
- 可简短更新稳定的项目约定。检查不替代独立 Judge 验收。
