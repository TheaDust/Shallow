## Builder 开发检查

使用文件工具和 `shell` 完成必要的开发检查。Windows 的 shell 使用 PowerShell；Linux 使用 Bash。按需编写和运行传统测试、类型检查或短命令检查，报告实际执行结果。

- 每个调用只执行与本次改动有关的检查；发现缺陷后针对性修复并复查。
- 端口合同：应用必须能在仅设置 PORT（未将 ARC_EXTRA_PORTS 设为 0）时启动，并让 PORT 与平台运行合同里列出的额外端口都服务同一个应用；额外端口要用各自独立的 http server 实例（同一个 Server 不能 `listen()` 两次），必须监听所有网卡，未知路径返回 404/错误且进程不退出。自检仍以 ARC_EXTRA_PORTS=0 PORT=<探针端口> 启动，不要占用额外端口；控制器会在交付验证时按评测方式复验 PORT 与这些额外端口。
- 复杂或边界逻辑（状态机、计算或公式、权限边界、事务与输入边界等）必须编写并运行传统测试；测试代码归入应用自己的测试目录与脚本，不得破坏平台合同要求的安装、构建与启动命令。
- `browser` 工具是昂贵操作（启动真实 Chromium、加载完整页面）：仅当构建、类型检查与传统测试无法回答真实浏览器行为问题时，用它验证本包最关键的一两条路径。使用时按平台合同在后台短暂启动应用、等待健康检查通过，检查结束后停止自行启动的应用进程。
- 控制器在本次调用结束并释放进程后执行安装、构建和独立浏览器检查。从控制器提供的白名单失败观测修复问题；开发检查不授予任何验收结论。
- 检查交互控件的可访问名是否稳定、具体，同类控件是否能区分；对话框打开后背景控件不可操作。按角色视角抽查本包改动涉及的页面结构：标题能被 heading 角色找到、对象条目与操作入口能被 button 角色按名称找到、输入框能按 label 或 placeholder 找到、表格数据能被 row/cell 角色遍历、对话框能按其标题名找到、操作反馈能被 alert/status 角色找到。优先在传统 DOM 测试中断言这些角色结构（React 项目用 @testing-library/react 的角色查询）；常规检查无法确认真实浏览器可访问树时，再用 browser 工具验证最关键一条角色定位路径。
- 保留种子数据。应用持久化使用 SHALLOW_DATA_DIR 指定的数据目录，未设置时使用应用自己的缺省目录；应用运行期间源码和构建产物保持不变。
- 可简短更新稳定的项目约定。检查不替代独立 Judge 验收。
