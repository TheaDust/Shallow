## ARCHITECTURE.md 交接约定

在项目根维护 ARCHITECTURE.md，帮助新会话快速回答：这类改动从哪里入手、谁拥有状态、需要遵守什么约束、会影响哪些路径、到哪里复查。内容描述当前代码事实；需求与平台合同决定目标行为，笔记中的实现信息须以代码核对。

开始工作时先读笔记的导航和本包相关约定，再按路径与符号读取相关实现。首次建立可复用的项目结构时创建笔记；每次实现或修复改变下列事实时，原位更新对应条目并清除过时描述，没有变化时保持不动。

### 内容与顺序

1. **代码导航与改动入口**：开头简述运行入口与主要领域边界；用紧凑表格记录「职责/改动类型 | 实现路径与关键符号 | 依赖及受影响处 | 相关测试」。按领域或共享能力组织，优先指出页面/状态编排、请求封装、后端入口和领域实现之间的连接。路径以项目根为基准，符号应能在代码中检索；只列能帮助定位修改的文件，完整目录树由文件系统提供。
2. **状态归属与关键数据流**：说明权威数据由哪个模块持有、怎样持久化，哪些值是派生结果或临时 UI 状态，以及刷新、重启、切换对象后的生命周期。给出关键对象的身份键、归属和关联；对跨模块操作，用一条代表链连接界面事件 → 请求/领域入口 → 校验与写入 → 重新读取/视图更新，标明实际负责的文件或符号。
3. **共享接口与修改约束**：记录后续模块真正需要复用的函数、类型或请求合同，注明输入/输出中的关键语义和调用前提，并指向权威定义。优先写容易被局部修改破坏的事实：权限判断位置、批量更新的原子性、拒绝操作时保留的状态、缓存/派生值失效、撤销范围、共享组件与多视图同步。约束后注明受影响调用方；必要时用一句解释决定实现方式的原因。字段全集、逐条 API 和控件文案通过源码定位，只保留跨模块必须一致的部分。
4. **种子关系与场景准备**：记录种子定义的文件/符号、初始化时机、共享对象的身份与归属、关键权限关系。精确数据以种子源码为准；笔记保留跨模块引用和同名对象区分所需的值。互斥初态注明通过现有公开操作建立状态的入口和前提，后续会话据此延续共享初态。
5. **复查入口与当前限制**：指出领域测试、集成测试、共享 fixture/mock 的位置和各自覆盖的边界，特别注明与生产逻辑重复、改动时需要同步的实现。只保留会改变开发方式的环境限制或陷阱，并附相关位置。确实存在且会误导续做的未接通环节，简述位置、当前行为与影响；接通后删除或更新该条。

### 更新与完成条件

按职责合并条目，保留当前约定；改名、拆分、接口或状态归属变化时同步修正路径、符号和调用关系。实现事实、约束和当前限制分别写清，测试结果与本次任务进度放在回执中。只维护本包改变或发现过时的部分，省略没有实际内容的栏目。

用短句、条目和紧凑表格保持可扫读，最多 200 行且不超过 16 KiB；按后续修改价值取舍内容。已有笔记过长且本包需要更新时，先合并重复描述，将大段枚举替换为权威定义的路径与符号，保留状态归属、跨模块约束和准备路径。

交接前核对本次涉及的笔记条目：路径和符号存在，描述与当前实现一致；新会话能够据此定位改动入口、识别需要同步修改或复查的位置，以及尚存的边界。
