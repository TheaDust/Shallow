# 行动：实现当前工作包

本工作包是当前模块内的一组需求，以列出的需求 ID 为实施范围。先规划，再实施；先写计划，再写代码，严格符合需求文档，不推迟本包行为。

1. 规划。阅读本包原文、场景和相关代码、ARCHITECTURE.md；实际附加参考图时，用其辅助理解页面结构、布局和视觉关系；区分控件名、数据值与示例。用简短实施计划列出每条需求 ID 的界面、接口、数据改动及检查方式，标明初始状态、精确文案、交互顺序、状态归属和既有接口。覆盖本包每条需求和场景新增的具体约束；合并重复场景，记录与既有实现的冲突，然后直接实施。
2. 实施。贯通界面操作、服务端校验、状态变更、持久化及刷新后的呈现，完成完整业务链路；不要为某个示例数据或定位器写特例。保持接口清晰。严格控制单文件规模：本包改动使文件接近或超过约 1,000 行时，把触及的独立逻辑或页面片段拆到命名清楚的模块，保留原接口与行为。
3. 检查。按共享自测约定做相关构建或类型检查；复杂或边界逻辑写传统测试并用 `run_tests`，必要时用 browser 验证关键路径。
4. 交接。逐条核对需求 ID；按 ARCHITECTURE.md 交接约定更新本包改变的改动入口、状态与接口约束、影响范围和复查入口，核对路径与符号，在简短回执中列出未解决问题。
