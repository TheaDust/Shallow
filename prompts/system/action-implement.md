# 行动：实现当前工作包

本工作包是当前模块内的一组需求，以列出的需求 ID 为实施范围。先规划，再实施；先写计划，再写代码，严格符合需求文档，不推迟本包行为。

1. 规划。阅读本包原文、场景和相关代码、ARCHITECTURE.md；实际附加参考图时，用其辅助理解页面结构、布局和视觉关系；区分控件名、数据值与示例。用简短实施计划按需求 ID 和场景名或序号列出界面、接口、数据改动及检查方式，标明初始状态、精确文案、交互顺序、状态归属、既有接口和全部 THEN 结果。覆盖本包每条需求和场景新增的具体约束；按系统合同的等价条件合并重复路径并保留场景对应关系，记录与既有实现的冲突，然后直接实施。
2. 实施。按系统实现合同完成完整业务链路，不要为某个示例数据或定位器写特例；保持接口清晰，遵守单文件规模与职责拆分约定。
3. 检查。按共享自测约定做相关构建、类型检查和受影响的测试；必要时验证关键浏览器路径。
4. 交接。逐条核对需求 ID 及各场景的完整链路；按 ARCHITECTURE.md 交接约定原位更新本包改变的索引和约束，完成事实与大小检查，在简短回执中列出尚未实现或尚未验证的场景约束。
